# _shared · 机器可读规则（不是 skill，不参与触发）

给 `plan-lint` / `prize-calc` / `{{可选工具·表格读取}}` 读取用的规则数据源。

## v2.0：从「写死规定」改成「场景驱动」

以前把 {{VERSION_NAME}} 一个方案的参数（{{CHANNEL_COUNT}}家渠道、{{BUDGET_AMOUNT}}~720 头奖、精确等额权重、T-45、7 条风险）
写成了全局规定，换个平台、换个节点就到处误报。现在规则分三层：

| 层 | 放哪 | 能不能改 |
|---|---|---|
| **① 硬红线** | `rules.json` → `layers.hard` / `redline_words` / `delivery` | **任何场景都不许改**（内容红线、数据纪律、外发交付、算术） |
| **② 场景参数** | `profiles/*.json` | **必须随业务背景变**：渠道、平台、节点、预算、奖池、任务、口径、排期、脱敏 |
| **③ 历史基线** | profile 里的 `note` / `baseline_ref` | 只作参照，标 A/B/C 证据等级，不作验收阈值 |

## 文件

- `rules.json` —— 硬红线 + 派生规则说明 + 缺省值 + profile 目录与默认档
- `profile_loader.py` —— 共用加载器：支持 `extends` 多级继承、子档只写差异、硬红线强制回填
- `profiles/base.json` —— 通用缺省（无渠道、无金额、无日期）
- `profiles/channel_prebook.json` —— **默认档**：{{SERVER_LINE_A}}·预约期·{{CHANNEL_TYPE_A}}{{CHANNEL_COUNT}}家（{{VERSION_NAME}}）
- `profiles/channel_version_week.json` —— 同渠道换节点：任务链、主指标、禁用词、投入档位全变
- `profiles/community_cps.json` —— 换平台：{{CHANNEL_E}}单渠道 CPS + H5 积分制（无加速、无权重、无梯度奖池）
- `profiles/platform_resource.json` —— 换服线：{{SERVER_LINE_B}} {{PLATFORM_A}} 平台资源位（CTR 主口径、无 {{APPROVAL_PARTY}}审批、无实物奖池）

## 怎么用（三句话）

1. 开工先**选档**：`--list-profiles` 看有哪些，选最接近的；差异大的新建一个继承 `base` 的 json。
2. 出稿体检带档：`lint_plan.py <方案.html> --profile <档id>`（不带则用默认档）。
3. 算奖品带档：`prize_calc.py prizes.csv --profile <档id>`。

脚本会从档里取渠道名单、价带、份数结构、权重顺序与容差、卡占比、盘子阈值、排期锚点、
必备风险、脱敏词表。**不适用某一项时是整组跳过，不是报警。**

## 新增业务场景怎么做

新建 `profiles/<id>.json`，`extends` 指向最接近的档，只写差异项。至少要覆盖：

```
service_line / node.type / goal / budget.model / channels[] / prize.model / metrics.comparable / schedule.needs_de_approval
```

覆盖任何默认值都要在 `overrides_log` 写一条（日期 / 改了什么 / 从什么改成什么 / 为什么）。
**覆盖理由写不出来，就说明不该改。**

## 维护约定

1. 改准则或红线时同步 `rules.json`；改某一场景的参数只改对应 profile，**不要改全局**。
2. 脚本只读 `rules.json` + profile，不硬编码渠道名、金额、日期、渠道数量。
3. 人读版：`../REDLINES.md` 第零章；准则版：`_shared/REDLINES.md` v2.1 的 0.1（自适应总则）/ 0.2（现实边界线）。全 skill 使用地图：`../README.md`。
4. 改之前先 grep 现状，别照记忆改。
