# 游戏发行运营红线（共享参考）

被 `channel-context` / `channel-selection` / `channel-plan` / `content-brief` / `creator-partnership` / `community-ops` 共同引用。
修改本文件等于改所有 skill 的边界，改之前先说一声。

## 零、哪些是「不许自适应」的（{{AS_OF_DATE}} 定）

规则按场景驱动（见 `_shared/规则三层说明.md` 与 `README.md`）：渠道、价带、件套、指标、排期都随场景档变。
**但下面这些是硬红线，任何场景档都不得覆盖，脚本恒检查**：

1. 本文件第一~四章全部内容（社区性质 / 创作者合作 / 投放素材 / 数据复盘）。
2. 数据纪律：不可比口径不相加、折算值不与实测相加、比率分母不可被渠道单方操纵、数值必须标证据等级。
3. 交付：对外 html 自包含（外部引用 0）、外发前脱敏、单文件打开自检。
4. 算术与同源：单价×数量＝行总价值、渠道小计之和＝总盘子、正文与表格同源。
5. 合规：跨区投放授权、素材授权、商业合作披露。
6. **现实边界线**（`rules.json` 的 `reality_guard`）：不得承诺自己交付不了的游戏机制或数据互通；带时点数字必须标出处；社区敏感表达。`plan-lint` 恒查并报 `REALITY-xx`。

**判断法**：跟业务对不上的规矩，先问它是「硬红线」还是「场景配置」。是配置 → 换档/建档并在 `overrides_log` 留痕；是硬红线 → 方案改，规矩不动。

> **机器可读版：`_shared/rules.json`**（供 `plan-lint` / `prize-calc` 读取）。
> 改这里的红线要同步改 `rules.json` 并更新 `updated` 字段——两处不一致脚本就会按老规则查。

## 一、社区性质类（按 {{GAME_CN}} 的实际情况填）

1. **禁止任何与游戏商业口碑冲突的表达。**
   先填 `{{GAME_FACT_*}}`：这款游戏卖什么、不卖什么。若口碑建立在「只卖时间和外观、内容可免费获得」之上，就不能写「变强捷径 / 氪金无敌 / 付费领先 / 速成战力」；可以写「省时间 / 外观个性化 / 支持开发者 / 提前体验」。

2. **禁止官方居高临下的口吻。**
   `{{DEVELOPER}}` 的人设若是「和玩家一起做游戏」，就用「我们也在玩 / 我们一起」，不用「官方通知 / 敬请期待 / 权威发布」。

3. **`{{SERVER_LINE_B}}` 与 `{{SERVER_LINE_A}}` 信息不可混淆。**
   数据是否互通、有无交易系统、定价差异，按事实填进场景档；任何涉及服务器的表述必须显式点名是哪个服。

4. **事实必须可溯源。**
   数值、日期、机制改动一旦说错，资料站与社区会逐条纠错。引用时标注「官方口径 / 官方未公布·第三方估算」；没把握就写「以官方公告为准」。

## 一之补、文化主题内容专项（本期涉及才用）

1. 文化主题产品卖的是**外观与文化设计**，严禁任何强度/数值暗示。
2. 文化表达要克制准确，不得出现事实性错误的典故。
3. 面向对应地区玩家时，专有名词首次出现给本地语言注解；不得编造官方没有的译名。
4. 不用夸张营销腔形容文化内容——与社区调性冲突时尤其克制。

## 二、创作者合作类

5. 创作者内容**不代笔成官方口吻**，保留其本人风格；只给事实边界和 must-have，不给逐字稿。
6. 商业合作必须**显式披露**（平台规则 + 投放地区法规）。
7. 不要求创作者说自己做不到或不认同的话。

## 三、投放与素材类

8. 素材不得使用未经授权的玩家二创、音乐、字体。
9. 不得在未确认区域授权的情况下跨区投放。
10. 预估/承诺类数字一律不出现在对外物料中。

## 四、数据与复盘类

11. 复盘结论必须区分「归因明确」与「相关性推测」，不许把相关性写成因果。
12. 声量类指标必须与负面声量占比一起看，只报正面数据是自欺。
13. **内部排期口径 ≠ 对外事实。** 方案内部可按内部排期推进，但对外物料里的上线日期、版本内容、合作身份，发布前必须与官方公告复核；官方未公布的，不得以既定事实口吻写出。
14. **只承诺渠道能回传的指标。** 渠道侧统计不到的结果不要写进目标表——写了验不了，还会逼出假数据；改用渠道确实能回传的替代指标，并登记进场景档 `metrics.forbidden`。参与人数是否去重、加速类是否报环比，一律以场景档为准。

## 五、交付与文件类

15. **外发先分内外。** 同一份方案给内部看和给外部合作方看是两个版本：历史基线、各渠道参与人数、环比这类内部数据默认不出现在给合作方的版本里。发出去前先问一句「这份要给谁看」。
16. **离开本机的 html 必须自包含。** 图片一律内嵌，生成后校验外部引用为 0。验证方式＝把文件拷到一个空目录双击打开——对方的环境就是这个样子。
17. **改文件前先 grep 现状。** 需求方会直接手改，工具也可能注入脏属性，照着上一版记忆改必错。
18. **同一数据只维护一处。** 会同时出现在正文总表、备选清单、图片链接表的数据，必须定死同步清单；维护两份必出现数字打架。

## 快速自检（每条素材/每份方案发布前）

- 这条内容会不会被读成「花钱就能变强」？
- 会不会被当成官方通稿？
- 说的到底是 `{{SERVER_LINE_A}}` 还是 `{{SERVER_LINE_B}}`？
- 里面的数字，我能指出处吗？
- **这个数字，渠道真的能给我吗？**
- **这份是给内部还是给外部？该拿掉的数字拿掉了吗？**
- **对方打开这个文件时，图还能看得到吗？**

七个问题有一个答不上来，就不要发。
