# 社区运营与舆情

{{GAME_CN}} 社区是"高参与度 + 高纠错能力"型社区。运营姿态不是管理，是**在场**。
先当玩家，再当官方。在 社区论坛 / {{COMMUNITY_FORUM}} / 论坛社区这类社区型渠道，**先参与后发声**——没有参与历史的账号发官方内容，会被当成入侵。

## 开工前

读 `_shared/context-template.md`（人群、渠道台账、口径）+ `../REDLINES.md`；准则层真源 `_shared/REDLINES.md` 第七章（内容红线）与第十一章（历史基线，判断"这期算好还是不好"）。
确认：本次是日常运营 / 节点沟通 / 还是危机处理（路径完全不同）。

## 一、日常节奏（cadence）

按版本节拍排，不按日历平均排：

| 时机 | 动作 |
|---|---|
| 每周 | 监听汇总（提及量、话题分布、负面占比）、常规答疑 |
| 版本前 | 铺垫、事实对齐、收集玩家疑问清单 |
| 版本当天 | 同步信息、盯首日反馈、快速纠偏错误解读；**顺手盯一眼活动页首屏**——「一键入库」是否第一格、回归入口是否独立（埋深了历史只做到 {{BASELINE_VALUE}} 与 {{BASELINE_VALUE}}） |
| 版本后 7 天 | 回声放大（好的二创、好的攻略）、遗留问题回应 |
| 收口 | 未核销 CDK 5 个工作日内回收；**结论回写两处**（见第四节第 4 步） |
| 重大节点 | 年度发布会 / 联动 / 文化主题版本发布：专项社区计划 |

产出：一张节奏表 + 一份"本周社区摘要"（话题 / 情绪 / 待处理项 / 需要升级的）。

## 二、监听

必听渠道：主要社区渠道（社区论坛、官方论坛、社群、社交平台、视频站、评论区）。
记录维度：提及量、话题聚类、**情绪分布**、关键意见者说了什么、有没有事实性误解在扩散。

**事实误解是第一优先级**——它传播快且会永久污染认知，发现即纠。

**两条口径纪律**（准则 2.4）：
- **声量类指标必须与负面声量一起看**，只报正面数据是自欺。
- 社区侧的提及量、讨论量属**不可比口径**，不得与渠道报的参与人数相加；判断是否"好"，去准则文件第十一章取历史基线对照。

## 三、分级响应

| 级别 | 判定 | 响应 |
|---|---|---|
| L1 日常 | 个别吐槽、常规提问 | 24h 内常规回应，不升级 |
| L2 聚集 | 同一议题出现 3 处以上讨论、情绪偏负 | 4h 内确认事实，出统一口径，指定发言人 |
| L3 危机 | 大规模负面、涉及商业化信任、或事实错误被当成真相扩散 | 1h 内响应，成立临时小组，每 4h 更新一次口径 |

## 四、危机处理四步

1. **确认事实**：到底发生了什么，我们说的是不是错了。错了就认。
2. **定性**：是误解、是失误、还是社区价值观冲突（后者最危险）。
3. **出统一口径**：一份文档，所有发言人同一版本。**禁止多人各说各话。**
4. **复盘写回两处**：
   - `channel-context.md` 的决策日志（结论，不记过程）
   - **准则文件 `_shared/REDLINES.md` 第八章**（新踩的坑，标注 A~F 根因分类：事实锚点 / 口径 / 活动设计 / 奖品预算 / 文档工程 / 交付形态）。⚠️ 改之前先 grep 现状，别照着上一版记忆改。

{{GAME_CN}} 专属：**涉及"付费变强"质疑时，绝不辩解，立刻把沟通切回内容向与时间向。** 辩解会被截图传播。

## 五、禁语清单

- "官方高度重视" / "敬请期待" / "感谢您的理解" —— 官方腔
- "氪金" / "变强捷径" / "战力领先" —— 触犯社区底线
- 未确认的时间承诺、未公布的数据暗示
- 把{{SERVER_LINE_A}}和{{SERVER_LINE_B}}混在一起说
