# {{SERVER_LINE_B}} {{PLATFORM_A}} 站内活动 · 方案与页面设计

## 这个 skill 解决什么

把「这个版本在 {{PLATFORM_A}} 站内做一个什么活动页」写成**三份各司其职、互不打架的交付物**：

| 交付物 | 形态 | 读者 | 只放什么 |
|---|---|---|---|
| **纯活动方案** | md，严格 4 章结论态 | 评审 / 执行 | 活动是什么 / 做什么任务 / 发什么奖 / 用户怎么走 |
| **规则与资料文档** | md，分节 | 内部 / 策划 | 约束、考量、出处、红线、待确认、逐轮验收、资料地图 |
| **页面设计图** | 单文件 HTML，零外链，双击可开 | 视觉 / 前端 | 玩家**看得见、点得动**的交互件 |

它的价值不只在创意，更在**边界**：方案、参考规则和玩家可见页面必须分层。见 `references/generic-retro-and-path.md`。

## 开工前必问（顺序不能跳）

**事实 → 口径 → 目标 → 边界 → 活动 → 奖品 → 排期**。缺一件就问，不要自己填（准则 10.1）。

1. **事实锚点**：版本名 / 节点性质（**预约期 or 版本周**）/ 服线 / 官方已公布到什么程度 / **本期活动目的**（触达已预约存量 or 预热扩散拉新——它决定页面放不放分享 / 扩散类组件，实践验证）。官方只给窗口没给日期的，写两套预案，**不把猜测写死**。
2. **口径**：四类玩家怎么切分、渠道能回传哪些指标、**跳转类能否埋点**、奖励归属与去重。
3. **核心目标**：收敛到 2 个以内（本案＝拉新 + 拉回流）；留存类任务只作补充，不并列核心目标。
4. **边界**：先确认「三份交付物各放什么」（见下节四层职责），再动笔。
5. **奖品四条约束**：预算盘子 / 份数结构 / 权重 / 红线——**必须在选品之前落地**。
6. **用户确认**：交付形式、是否导入在线文档、旧文档何时覆盖。本案全程「先讨论清楚、定稿后再覆盖」。

> 复盘结论：四版迭代里真正的内容返工只有两次，一次是事实锚点没核实、一次是奖品约束没先定。**返工不是写错，是开始得太早。**

## 四层职责（本 skill 的骨架，不许越界）

| 层 | 内容 | 唯一落点 |
|---|---|---|
| 玩家可见交互层 | 导航 / 首屏 KV 与主按钮 / 任务卡（任务名＋条件＋奖励＋`+N 次`＋`0/N`＋按钮三态）/ 奖池 / 剩余次数 / 我的礼包 / 中奖名单 / 概率公示 / 规则弹窗 / 签到条 | **只放 HTML 页面设计图** |
| 任务判定口径层 | 限次 / 资格定义 / 发放渠道＋时点 / 触发计数 / 去重 / 上限 / 状态说明 | **纯方案第二章备注列** |
| 用户路径与归属层 | 四类玩家各参与哪些任务、奖励谁得几次、领奖渠道 | **纯方案第四章流程图** ＋ 对应参考文档口径节 |
| 规则 / 出处 / 验收层 | 红线、禁用词、译名、日期纪律、待确认、逐轮验收、参考页借鉴 | **只放对应参考文档** |

**一句话**：页面设计图＝玩家在 {{PLATFORM_A}} 活动页真正看得见、点得动的交互件；凡「为什么这么算、谁归谁、内部怎么判定」一律不进页面。逻辑是**归位不是删除**，纯方案不因此改动一字。**页面不点明玩家身份、不搬运营分层口径；方案必须保留分层逻辑**；对齐只查关键规则 / 触发条件 / 分层结果一致，允许粒度与表述差异（{{AS_OF_DATE}} 写死，详见 `references/page-boundary.md` 原则块 ＋ `references/acceptance.md` 三之二节）。

## 执行主链路（八步）

**Step 0 · 建地图（最先做，不可跳）**
按 `references/material-integration.md`：只登记元信息（文件名 / 路径 / 类型 / 来源 / 行数），**不读正文**。产出一张清单给{{OWNER_ROLE}}看「总共有什么、大概在哪」，并说明这轮准备取哪几份、用来做什么。地图没建完不许读内容。

**Step 1 · 核实事实**
官方译名（{{SERVER_LINE_B}}官网 / {{PUBLIC_REFERENCE_SOURCE}} 简中）、服别归属、日期窗口、参考页哪个 tab 才是原文、梗词三档（可直用 / 需改造 / 禁用）、机密材料的公开性边界。核实结论连同来源写进对应参考文档，**不写进方案出处**。

**Step 2 · 定边界与拍板项**
确认三份交付物分工 + 四层职责；用选择控件把拍板项写死（交付形式 / 服线 / 节点性质 / 旧文档处理方式）。不确定项一律登记【待确认】＋占位，不预设具体日期、奖品型号、概率、档位。

**Step 3 · 写纯方案**（`assets/plan-template.md`）
4 个 H2 固定：一、活动概述（5 个加粗 bullet）／二、任务设置（三列表，**任务类数 / 分组以当期纯方案为准**）／三、抽奖奖品设置（六列表，数据行全占位）／四、活动交互示例（纯文本树状用户路径流程图）。骨架与备注列规律见 `references/plan-outline.md`。

**Step 4 · 写对应参考文档**（`assets/rules-doc-template.md`）
复用资料地图六节骨架，按「留 / 移 / 拆」把框架版内容搬入；补版本背景边界、玩家梗词库、逐轮验收节。**方案之外全归它**——正文不出现「待确认 / 出处 / 验收 / DDL / 内部资料 / 工具调研」。

**Step 5 · 做页面设计图**（`assets/page-wireframe.html`）
复用线框骨架的 CSS 组件，文案全量换当期口径；单文件、纯静态、零外链；奖品 / 日期 / 概率 / 价格一律占位。屏注＝数字「▼ 第 N 屏 · 屏名」**或**非数字「▼ 独立模块 · X」；**新增整屏模块用后者、不重新编号**（避免牵动后续屏号与对应参考文档历史记录）。对照真实 {{PLATFORM_A}} 活动页补齐交互件，**只借活动方式与交互结构，专有名词零搬入**；补邀新机制先看自家真实邀新页原型（`tools/act-scrape`，按命中数只精读贴题的少数页）。三条硬规矩：**组件配色全站统一**（任何模块不得用全站唯一的特殊配色）／**占位面积与同排文字量匹配**（禁小方块配大留白）／**任务清单项数、签到档位以当期纯方案为准**。详见 `references/page-boundary.md`。

**Step 6 · 每轮收口固定四件事**
① 对应参考文档同步（表述优化记录 ＋ 新增验收节 ＋ 红线 / 词表 / 待确认）② **回头扫本 skill 全部 `references/` 与 `assets/` 模板**（含写死项）把本轮新决策写进去 ③ 联合自检 ④ 工作日志追加本轮段落。**未点头的结构性提案登记为「待定」，不得写成现行规定**（历次迭代连续 5 轮未回头扫 skill，是 skill 落后的直接原因）。

**Step 7 · 自检分「当期真源」与「留痕」**（`references/acceptance.md`）
只对纯方案正文 ＋ HTML 正文要求旧词零命中；对应参考文档里的旧词命中先按**留痕分类表**（A 带时点真留痕 / B 无时点旧规格 / C 失效指针）分类再判，**绝不批量抹掉**。固定项：禁词 grep、HTML `div` 开闭配平、零外链、结构计数、表格列数一致、真实交互件在位、「逻辑词在纯方案 True / HTML False」；**外加屏序断言（基准取当期 HTML ＋ 对应章节，不再以历史提案为基准）、配色全站统一、占位比例、无累赘解释小字**。断言区间收紧到紧邻边界，失败不写回。

**Step 8 · 交付闸门**
本地三份先给用户确认；**再次明确确认后**才覆盖旧在线文档，覆盖前脱敏自检。外发 HTML 用内联 CSS 自包含、单文件零外链，拷到空目录双击自检一遍。

## 最优路径（给定任务走哪条最短）

| 任务 | 最短路径 | 别做的 |
|---|---|---|
| 出一个新版本站内活动页方案 | 建地图 → 核实事实 → 定边界 → 纯方案 → 对应参考文档 → 页面设计图 | 别一上来配奖品（约束没定会返工）；别先画页面（边界没定会整批清出） |
| 只改任务口径 / 奖励归属 | 改纯方案备注列 ＋ 第四章流程图 → 同步对应参考文档口径节 → 联合自检 | 别把「为什么这么算」画进页面；别只改页面不改方案 |
| 只优化文案 / 包装名 | 先核实官方译名与梗词三档 → 改纯方案 H3 与括号注 → 同步 HTML → 同步词表 | 别换意象时顺手改机制；别把社群叫法写成正式名 |
| 复盘对齐 / 剔除矛盾 | 建地图 → 分类（带时点真留痕 vs 无时点旧规格）→ 只清 B 类 → 验收留痕 | 别通读全文；别一句「历史留痕不动」打包背书；别把验收记录一并抹掉 |
| 归档精简 / 删文件 | 先 grep 全项目（含隐藏目录）判引用性质 → dry-run 打印 KEEP → 回收站 → 复扫 → 留痕 | 别因「看着旧」就删；别用硬删；删了断证据链的别动 |
