## 模板使用说明（落稿时删除）

1. **四个 H2 顺序固定、不多不少**；标题格式 `# 【渠道】<游戏名><版本>版本活动`；H1 下一行必须是**加粗福利导语**。
2. **概述恰 5 个加粗 bullet**，字段名逐字沿用：`活动主题 / 活动时间 / 投放平台 / 核心目标 / 奖励预算`。首屏福利落点见当期纯方案（福利导语、奖励预算 bullet、第四章流程图首屏节点），处数按当期、不写死。
3. **活动时间不写具体日期**（官方未公布日不得写死）；**核心目标不写「不覆盖 / 不结转 / 不冲突」等防御性表述**。
4. **备注列只写判定口径六类**：限次 / 资格定义 / 发放渠道＋时点 / 触发计数 / 额外归属 / 状态说明。禁营销话术、道具罗列、概率预算、UI 描述、口播句；时间口径用通用口径，不留空、不写具体日期。
5. **润色句只放任务条件的行内括号注**，不进备注列、不进任务条件主干、不进奖励内容。
6. **奖品数据行全部占位**：型号 / 单价 / 概率 / 档位本轮不写，先登记【待确认】。
7. **纯结论态**：正文不出现「待确认 / 出处 / 验收 / DDL / 内部资料 / 工具调研 / @人 / 约束 / 考量 / 规则」。这些一律进独立对应参考文档。
8. **流程图＝纯文本树状代码块**（不带语言标记，`→ │ ├─ └─` 分支按四类玩家分组），**不用 Mermaid / 技术路线图、不主动加可视化大图 / 附加读图段**；里面的**归属推导、去重口径、次数上限**要写清，且与对应参考文档口径节一致；页面设计图里不重复。
9. 全案不出现 `{{FORBIDDEN_TERM}}`；{{SERVER_LINE_B}} / {{SERVER_LINE_A}}术语不混用；「预约」按语义判定（允许作人群指代，禁作包装名 / 机制词）。
10. 骨架细则见 `../references/plan-outline.md`，自检见 `../references/acceptance.md`。
11. **与当期纯方案冲突时以纯方案为准**；示例流程图只作形式、节点不得写成全局规定；有意差异（页面占位 vs 方案确定值、预算脱敏、流程图不进页面）登记保留。
12. **页面 vs 方案分工见对应参考文档 对应章节**（`acceptance.md` 三之二节）：本方案必须保留玩家分层逻辑与各层处理口径；页面设计图不显式点明身份、不搬运营分层口径；对齐只校验关键规则 / 触发条件 / 分层结果一致，允许粒度与表述差异，不逐项硬比。
