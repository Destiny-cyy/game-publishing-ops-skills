# 活动方案与页面设计复盘模板

> 这是通用检查清单，不含具体游戏、客户、内部归档编号或历史项目结论。

## 常见返工原因

| 根因 | 典型表现 | 预防动作 |
|---|---|---|
| 事实未核实 | 译名、服线、日期或活动状态写错 | 先记录公开来源、核实日期与待确认项 |
| 开始过早 | 奖品、概率、排期尚未确认就进入页面 | 按“事实→口径→目标→边界→机制→奖品→排期”推进 |
| 边界不清 | 页面塞入内部推导和审批说明 | 将玩家可见页面、纯方案和参考文档分层 |
| 口径漂移 | 同一资格或次数在不同文件写法不一致 | 指定唯一真源，修改后扫描全部引用 |
| 装饰压过直观 | 视觉进度与真实任务无关 | 只展示可解释、可更新、可验证的状态 |
| 场景混用 | 不同服线、平台或渠道规则被直接套用 | 每个场景绑定独立配置与验收规则 |

## 推荐路径

1. 建立资料地图，只读取与当前页面有关的官方公开资料和已授权内部规则。
2. 填写 `{{GAME_CN}}`、`{{SERVER_LINE_A/B}}`、`{{PLATFORM_A}}`、`{{VERSION_NAME}}` 等场景配置。
3. 核实术语、日期窗口、资格、奖品、概率和隐私边界；未确认项保留占位符。
4. 先完成纯方案，再写规则参考，最后制作页面线框。
5. 页面只放玩家可见并可操作的内容；内部判断、审批和预算依据留在参考文档。
6. 每次修改后检查唯一真源、跨文件一致性、禁用词、敏感数据和外链。

## 页面交付检查

| 检查项 | 通过标准 |
|---|---|
| 信息层级 | 主任务、资格、奖励和状态一眼可辨 |
| 交互完整 | 默认、进行中、完成、领取、不可用和异常状态齐全 |
| 规则一致 | 次数、上限、去重和发奖与纯方案一致 |
| 响应式布局 | 手机和桌面均无重叠、截断或不可点击控件 |
| 对外边界 | 无内部编号、真实人员、客户资料、未公开日期和项目路径 |
| 技术边界 | HTML 自包含或明确列出外部依赖；外链均经过审核 |

## 停止条件

- 官方事实或权属来源冲突；
- 奖品、概率、预算或资格仍会实质改变页面；
- 页面需要未授权的数据、账号或平台能力；
- 发现具体项目敏感材料、个人信息或内部链接。
