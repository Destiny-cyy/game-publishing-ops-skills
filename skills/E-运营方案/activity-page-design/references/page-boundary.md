# 页面设计 vs 方案逻辑 · 四层边界与交互骨架

> **一句话原则**：页面设计图＝玩家在 `{{PLATFORM_A}}` 活动页**真正看得见、点得动**的交互件（线框示意）。
> 凡「为什么这么算、谁归谁、内部怎么判定」的解释，一律不进页面。

**身份与分层口径（固定口径，变更需留痕）**：
- 页面面向玩家：文案与交互**不显式点明玩家身份**（不写「你是新玩家 / 老玩家」判定语），**不搬用运营侧分层口径**（内部分群编号零出现），侧重玩家可读体验；身份差异只通过玩家自己能读懂的任务与奖励呈现。
- 方案面向运营：**必须保留玩家分层逻辑与各层处理口径**（谁得几次、怎么触发、上限多少）；**禁止因页面不写分层而删减方案分层**。
- **禁止把运营分层说明生搬进玩家页面**。

## 一、四层职责表

| 层 | 该放什么 | 唯一落点 |
|---|---|---|
| 玩家可见交互层 | 导航、首屏 KV 与主按钮、任务卡（任务名＋条件＋奖励＋`+N 次`＋`0/N`＋按钮三态）、奖池 / 剩余次数 / 我的礼包、概率公示、活动规则弹窗、签到条 | **只放 HTML** |
| 任务判定口径层 | 限次、资格定义、发放渠道 / 时点、触发计数、去重、上限、状态说明 | **纯方案备注列** |
| 用户路径与归属层 | 各人群参与哪些任务、奖励谁得几次、领奖渠道 | **纯方案流程图** + 规则口径节 |
| 规则 / 出处 / 验收层 | 红线、禁用词、译名、日期纪律、待确认、逐项验收、参考页借鉴 | **只放规则说明** |

**逻辑是「归位」不是「删除」**：清出页面后，归属口径、各人群路径仍完整留在纯方案与规则说明里，纯方案不因此改动一字。

## 二、必须清出页面的解释层组件

| 清掉的东西 | 归位到 |
|---|---|
| 奖励归属说明卡 +「奖励机会怎么算」对照条 | 纯方案对应任务备注列 + 规则口径节 |
| 「用户路径示意（各人群 × 参与任务）」导览屏 | 纯方案流程图 |
| 卡内资格判定小字（每人仅贡献几次、合计上限） | 纯方案备注列 |
| 进度条解释句 | 删（进度条只留玩家看得懂的 `3/5`） |
| 屏注里的内部包装名 / 口径 / 术语 /「快照示意，非实时」 | 屏注＝「▼ 第 N 屏 · 屏名」或非数字「▼ 独立模块 · X」 |
| 回归入口的人群定义说明 | 纯方案备注列 + 规则身份口径节 |
| 内部同事名、内部待办注记（「具体数值待奖池定稿」等） | 改玩家向占位（「奖品待公布」/「以页面公示为准」） |

**玩家不可见的残留也要清**：空的死 CSS 类、复制粘贴带进来的零宽字符 U+200B、旧包装名的 CSS 注释。历史沿用类名若改名需同步多处、收益低，可保留但登记为「历史类名，不作口径依据」。

## 三、参考活动页的交互骨架（只借方法，不搬内容）

只借**活动方式 + 交互设置**；参考页的世界观词条、核心意象、专有名词**不得写入本案文案**，一律换成本案调性词。归档页统一用「归档页 A/B/C…」指代，不写真实页面标识。

| 参考类型 | 可复用的交互件 | 本案借鉴 |
|---|---|---|
| 任务清单型活动页 | 导航 + 剩余次数 + 点击抽奖 + 中奖名单 + 任务清单（次数+1 / 0/1 / 0/5 / 去分享）+ 我的礼包 + 概率公示位 + 活动规则 | 任务清单换次数、`0/N` 进度、剩余次数、我的礼包、概率公示、按钮动作 |
| 里程碑型活动页 | 首屏大奖钩子、预约里程碑、每日登录 / 分享 / 邀请换次数、概率公示前置 | 首屏福利前置 + 里程碑 |
| 注册即领型活动页 | 新用户首次注册创角即得、分享换次数、页内概率公示 | 创角即领即时反馈 |
| 任务卡型活动页 | 任务卡文案 +「已领取 / 立即领取 / 未开放」三态 | **按钮三态 + 具体动作写法**；也是「把付费项放前列屏」的反例 |

### 玩家可见交互件清单（**指针，规格不写死**）

导航 → 首屏 KV 与主按钮 → 全服进度 → 任务卡（任务名＋条件＋奖励＋`+N 次`＋`0/N`＋按钮三态）→ 奖池 / 剩余次数 / 中奖名单 / 我的礼包 → 概率公示 → 签到条 → 版本情报 → 活动规则弹窗。
这里只保留「有哪些类」，规格（单 / 双按钮、栏数、档位、清单项数、屏号）随当期方案变，不在此写死；当期交互件与屏序一律以**当期 HTML ＋ 当期方案**为准。

### 屏序骨架（**指针 + 结构规则**，屏号不写死）

只留 5 条结构规则：
1. 新增整屏模块用**非数字屏注「▼ 独立模块 · X」、不重新编号**，避免牵动后续屏号；只在别的屏内「前置放大」不算独立。
2. 屏内**主模块在上、子模块在下**。
3. 奖励前置可作屏序直觉，但**整屏对调 / 屏号同步属大调整，先出对照图提案、确认后才执行**；未确认期间收到新反馈只处理点名项，被冻结的结构一律不动，写回前加「屏序未变」断言。
4. 浮层个数与是否含分享入口**由本期活动目的定**（触达已预约存量 → 不做预热扩散浮层；回流机制 ≠ 扩散机制，别一刀切）。
5. 当期屏序以当期 HTML ＋ 当期方案为准，模板不预定屏号。

## 四、直观性红线

- 进度条必须**和真实抽奖次数串成闭环**：`任务进度（3/5）` + `剩余次数：X`，亮格＝该任务已完成并领到 1 次机会。
- 删掉与抽奖进度无关的**纯装饰数字**。
- 小字写大白话：玩家看不懂的意象化表达，改成「奖品福利一览 · 有机会获得」这类直白说法。
- 抽奖区包装可换意象，但**机制一字不改**。

## 五、HTML 交付形态（硬要求）

- 单文件、纯静态、**零外链**，双击可开；`div` 开闭配平。
- 线框风格：**组件配色全站统一**（白底 / 1px 细黑边 / 黑字 / 灰底占位框 / 主按钮同款）——任何模块不得用全站唯一的特殊配色；整改只清「全站唯一」那一处，未点名模块的同款样式与窄屏规则一律保留。奖品 / 日期 / 价格 / 概率一律 `（待定）` / `X` 占位。
- **占位比例协调**：占位框面积与同排文字量匹配，禁「小方块配大留白」；用横向长条自适应，纯 CSS 改动、不动 DOM / 文案 / 屏序。
- **删累赘解释性小字**：等于没说的解释删掉；但「游戏道具领取时间」讲的是道具发放时点、非活动上线，**先分辨性质、未点名不动**。
- 屏注＝数字「▼ 第 N 屏 · 屏名」**或**非数字「▼ 独立模块 · X」，是**设计图元信息**，不是页面内容；不得夹带内部包装名或口径。
- 屏内不得出现「任务逻辑怎么算 / 各人群路径 / 备注列判定口径 / 快照示意，非实时 / 内部同事名」。
- 改前必 grep 现状，用户改动保留。

## 验收（页面维度）

- [ ] 逻辑解释词零命中：用户路径示意 / 一眼看懂 / 怎么算 / 导览 / 归属 / 进度不代表 / 快照示意 / 合计最多
- [ ] 真实交互件在位：我的礼包 / 任务进度 / 剩余次数 / 概率公示 / 按钮三态 / 活动规则
- [ ] 归属口径在纯方案 **True**、在 HTML **False**
- [ ] `div` 开闭配平、外链 0、零宽字符 0、无内部同事名 / 内部待办注记
- [ ] 当期交互件在位（以当期 HTML ＋ 当期方案为准逐项核对）
- [ ] 配色全站统一、占位面积协调、无累赘解释小字；屏注允许非数字独立模块
- [ ] **屏序断言**：写回前后各验一次，基准取当期 HTML ＋ 当期方案
