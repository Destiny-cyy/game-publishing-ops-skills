# 自检 · 验收 · 留痕分类表

> **一句话**：自检分「当期真源」与「留痕」两类。只对**当期真源**要求旧词零命中；对应参考文档里的命中先按留痕分类表判定，**绝不批量抹掉**。
> 「历史留痕不动」不能一句打包背书，必须逐类列出落点。

## 一、当期真源（唯一指到这几处，别扩散）

| 真源 | 范围 |
|---|---|
| 纯方案 | 第二章任务表备注列、第四章用户路径流程图 |
| 页面设计图 | HTML 正文（玩家可见交互件） |
| 对应参考文档 | 对应章节 计奖口径 / 对应章节 边界 / 对应章节 交互骨架 / 对应章节 定稿包装名 / 当期验收节 |

这四处要求：旧词、旧口径、内部待办注记、任务逻辑解释词**零命中**。

## 二、留痕分类表（先分类，再判命中）

| 类 | 判定标准 | 处理 | 本案落点 |
|---|---|---|---|
| **A · 带时点真留痕** | 有日期 / 轮次，记录「当时改了什么、验收查过哪些词」 | **保留，一字不改写**（改记录＝篡改历史） | 对应章节 历次迭代表述优化记录、对应章节 取用留痕、对应章节a~e 逐轮验收、§2 D2/D3/D4 一手摘录、对应章节 / 对应章节 停用词登记 |
| **B · 无时点旧规格（抛填矛盾）** | 无时点、却以现行规格语气书写，彼此打架或与当期真源冲突 | **剔除 / 压成指针** | 原 对应章节 候选包装名表、对应章节 逐屏模块表、对应章节 屏序行、对应章节 R3、对应章节 首屏规格、对应章节 / 对应章节 旧词 |
| **C · 失效指针与重复项** | 行号已漂移、待确认项重复、译名冲突已被绕开 | **修正** | 对应章节d 行号、§12 第 6 条、对应章节 |

> 判断顺序：Grep 命中 → 判类 → A 不动 / B 剔除 / C 修正 → 复扫。
> 「抛填矛盾内容」在**文档内部**（B 类），不在归档文件里；归档精简走 `material-integration.md` 的引用判定，两件事别混。
> **skill 自身同类**：`SKILL.md` / `references/` / `assets/` 模板里无时点、与当期真源冲突的旧规格也应压成指针或占位，处理原则见 `generic-retro-and-path.md`。

## 三之二、页面 vs 方案对齐口径（{{AS_OF_DATE}} 已确认，作为固定口径，变更需留痕）

> 细则见对应参考文档 对应章节；对齐检查一律按此执行，不逐项逐字硬比。

- **对齐只校验三样**：① 关键规则 ② 触发条件 ③ 分层结果，两边**一致对应、互不冲突**即通过。
- **不要求**：字段、文案、模块或全部内容逐项一一对应；**允许信息粒度与表述差异**（页面玩家向、方案运营向，侧重点本就不同）。
- **判「不对齐」的标准**＝关键规则 / 触发条件 / 分层结果**冲突或缺失**；文案写法不同属允许差异，不立项整改。
- **两个禁止**：禁止把运营分层说明生搬进玩家页面；禁止因页面不写分层而删减方案分层。整体不得生搬硬套。

## 四、脚本模式（临时脚本，跑完即弃）

- `pathlib.Path.read_text(encoding="utf-8")` / `write_text`；写回前**全部断言通过**，失败不写回（本案历次迭代、历次迭代各因一处前导空格 / 实际文本不符，历次迭代、历次迭代各因**断言区间取宽**把 CSS 类名 / 跨区块同值样式误计入，触发过 `AssertionError`，文件均未受损）。**断言区间收紧到紧邻边界**（下一个注释 / 目标 DOM class），排除 CSS 类名与跨区块同值样式。
- 历次迭代新增写回前断言：**屏序未变 / 配色 4 项齐备 / 占位长条生效 / 用户手改文案 N 条保留 / 未点头提案状态未变**（历次迭代后屏序基准改为当期 HTML ＋ 对应章节，历史提案不再作断言基准）；改前 Grep 选区词计数确认指代对象（历次迭代「首页」误抓实证）。
- `H.count(old) == 1` 防止误伤用户手改内容；`old_string` 按**当前磁盘实际文本**写。
- `splitlines(keepends=True)` 按精确行号删除整块；`re.findall(r"<div\b", H)` 与 `H.count("</div>")` 配平；`re.findall(r"https?://", H)` 查外链。
- Markdown 表格块列数一致性单独校验。
- 临时脚本放系统临时目录，不留在项目里制造归档垃圾。

## 五、红线速查（指针 §14 / `../REDLINES.md` 第零章）

一句话版（条数按当期，别写死）：无 `{{FORBIDDEN_TERM}}`／只写节点不写日期／不写具体奖品与概率／服线不混／不付费变强·不官方腔／与预约活动只共享用户不结转资产／签到无游戏内任务／不跑 `plan-lint` 默认档·不套 `platform_resource.json`／社区红线／梗词红线／页面设计边界红线／**页面视觉＝全站统一配色＋占位比例协调＋屏序大调整须点头**。

**自检七问**：付费变强 / 官方腔 / 服务器混淆 / 数字出处 / 渠道能给这数吗 / 给内部还是给外部 / 对方能看到图吗。

## 六、每轮收口四件事

① 对应参考文档同步（本轮表述优化记录 ＋ 新增验收节 ＋ 红线 / 词表 / 待确认）→ ② **回头扫 `references/` 与 `assets/` 模板（含写死项），把本轮新决策写进 skill** → ③ 联合自检 → ④ 当日 memory 追加本轮段落。
**带时点历史行保留，数字计数改指针不改数；未点头的结构性提案登记「待定」，不写成现行规定；已点头执行的提案按当期真源更新，不留过期断言。**

## 七、交付闸门

- 本地三份先给用户确认；**再次明确确认后**才覆盖旧在线文档，覆盖前脱敏自检。
- 外发 HTML：内联 CSS 自包含、单文件零外链，拷到空目录双击自检一遍。
- 未确认的投放（份数 / 预算 / 档位 / 概率）保持【待确认】，不带病上线。
