# 资料整合：先建地图 → 按需取用 → 每步留痕

> **适用场景**：手上有一堆参考文档、归档页、历史方案，要从中提炼可复用的方法，而不是通读后全量堆进正文。
> 本文件是通用方法，不指向任何具体项目的目录、日志或归档编号。

---

## 一、三条底线

1. **禁止通读**：资料多时先建索引，按任务需要取用。通读 + 全量堆进正文，几乎必然产出「太累赘」的稿件。
2. **每步留痕**：读过什么、用了什么、没用什么，都要能回答「这条结论从哪来」。
3. **指针不复制**：正文只放指针与结论，不复制原始材料里的数字与段落，避免两处失同步。

## 二、四步工作流

| 步 | 动作 | 产出 | 停止条件 |
|---|---|---|---|
| 1 建地图 | 列出所有资料：名称 / 类型 / 大致内容 / 可能对应的章节 | 一张资料索引表 | 每份资料都能被一句话定位 |
| 2 定需求 | 写清这次要回答哪几个问题，每个问题需要哪类证据 | 问题—证据对照表 | 问题和证据类型一一对应 |
| 3 按需取用 | 按索引命中数定位，只精读命中最高且最贴题的少数几份，其余不碰 | 摘录卡（出处 + 原文 + 用途） | 每个问题都有足够证据，或明确登记「证据不足」 |
| 4 留痕收口 | 记录 KEEP / 归档 / 不用的原因；正文只写指针 | 资料处置台账 + 正文引用清单 | 全项目零悬空引用 |

**正向样本**：从一批归档活动页里，先按关键词命中数定位，只精读最贴题的少数几页，其余不碰；再从参考页里提炼可复用的机制原型（双入口 / 门槛 / 邀请码 / 累计进度 / 达标领取）。这是「按需取用」最直接的用法——**借机制，不搬内容**。

## 三、检索要分作用域

至少扫这几类位置：项目根、技能目录、参考文档目录、模板目录、历史归档目录。只扫一次会漏隐藏目录与 `assets/` 模板里写死的旧值。

**删任何资料之前**：先全项目检索确认零引用 → 打印 KEEP 列表 → 走回收站 → 删后复扫一次。这一步不能省，模板里的写死引用照样会把人带沟里。

## 四、常见返工

| 返工 | 根因 | 预防 |
|---|---|---|
| 正文太累赘 | 通读后全量堆进去 | 先建地图，只取与问题直接相关的 |
| 结论找不到出处 | 没留摘录卡 | 每条结论绑定一份摘录卡 |
| 改了规则忘了改模板 | 只扫了正文 | 检索分作用域，把 `assets/` 模板算进去 |
| 删完发现还有引用 | 删前没扫全 | 删前检索、删后复扫 |

## 五、验收

- [ ] 资料索引表覆盖全部资料
- [ ] 每个问题都有证据，或明确登记「证据不足」
- [ ] 正文只放指针，不复制数字
- [ ] 资料处置台账写清 KEEP / 归档 / 不用 的原因
- [ ] 删改前后各检索一次，零悬空引用
