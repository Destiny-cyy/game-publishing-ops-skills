# 纯活动方案 · 4 章骨架与字段字典

> 纯方案＝**结论态**。只回答「活动是什么 / 做什么任务 / 发什么奖 / 用户怎么走」。
> 约束、考量、出处、红线、待确认、验收、DDL、工具调研**一律不进正文**，全归对应参考文档。
> 模板见 `../assets/plan-template.md`。

## 一、四个 H2（顺序固定，不多不少）

| H2 | 内容 | 硬要求 |
|---|---|---|
| **一、活动概述** | 5 个加粗 bullet | 字段名**逐字沿用**：`活动主题 / 活动时间 / 投放平台 / 核心目标 / 奖励预算` |
| **二、任务设置** | N 个 H3，每个一张三列表 | 列名固定 `任务条件｜奖励内容｜备注`；H3 带「模块 · 人群」标注 |
| **三、抽奖奖品设置** | 六列表 | 列名固定 `序号 / 奖品名称 / 中奖概率 / 数量 / 单价 / 总价值`；数据行**全部占位** |
| **四、活动交互示例** | 用户路径流程图 | **纯文本树状代码块**（代码块不加任何语言标记），按玩家类型分组；禁 Mermaid / 技术路线图 / 主动加可视化大图（硬约束见第四节） |

标题格式：`# 【渠道】<游戏名><版本>版本活动`；H1 下一行是**加粗福利导语**（首屏福利落点之一）。

### 概述 5 个 bullet 的写法
- **活动主题**：版本名 + 节点性质；主 KV 用版本主图作头图、下方延展贴合 KV 风格；版本背景**≤2 句**、只用官方已公开的情感向宏观叙事。
- **活动时间**：只写「XX 版本上线期」/「XX 预约期」，**不写具体日期**（官方未公布日不得写死）。
- **投放平台**：例如「{{SERVER_LINE_B}} {{PLATFORM_A}} 站内活动页」。开头即点明服线，全文不混淆。
- **核心目标**：收敛到 2 个以内，用「+」连接（本案＝拉新 + 拉回流）；可补一句正向触达对象，**禁写「不覆盖 / 不结转 / 不冲突」等防御性表述**。留存类任务只作补充。
- **奖励预算**：首屏即领 + 预算盘子量级；虚拟礼包格数。**这是首屏福利的第二处落点**。

### 首屏福利三处落点
① H1 下加粗福利导语；② 概述「奖励预算」bullet；③ 第四章流程图首屏节点高亮大奖钩子。

## 二、任务表三列（备注列是重灾区）

| 列 | 写什么 | 禁写什么 |
|---|---|---|
| **任务条件** | 具体动作 + **行内括号注（润色句 / 本案语感）** | 判定口径、限次、资格定义 |
| **奖励内容** | 奖励项，可带档位 | 概率、预算、型号、单价 |
| **备注** | **发放规则与要点**（见下） | 营销话术、道具罗列、概率预算、UI 描述、口播句 |

### 备注列写法规律（对齐参考 doc 原文归纳）
只写判定口径（下列 6 条为常见类别，实际类别与数量以当期纯方案为准，模板不写死）：
1. **限次**（每账号限 1 次 / 每日限 1 次）
2. **资格定义**（新用户＝该账号下无角色；回归用户＝超过 N 天未登录）
3. **发放渠道 / 时点**（游戏内邮件发放 / 活动结束后 30 个工作日内发放）——用通用口径，**不留空、不写具体日期**
4. **触发计数**（完成即触发 / 完成后手动点击领取）
5. **额外归属**（双方各得 / 每新玩家仅为 1 位邀请人贡献）
6. **状态说明**（每日 0 点刷新 / 逾期视为放弃 / 不可退队换队）

> 历次迭代踩坑：备注列原本写成「任务润色版说法」，全量换成判定口径后，润色句统一挪进任务条件行内括号。**一处只放一类内容**。

### 任务模块的常见分组（本案实例，非硬规定）
拉新（邀请有礼）／回流（人拉人组队）／留存（签到）／新用户标配（创角即领）／基础活跃 + 抽奖（任务清单换次数）／信息展示（版本情报，无奖励）；**回归模块在页面侧单独成屏、不挂在拉人 / 组队屏下**（见 `page-boundary.md`）。分组与数量以当期纯方案为准，此处只列「有哪些类」。
**7 日登录签到**：仅每天登录活动页面领取，无复杂游戏内任务。

## 三、奖品六列表

数据行一律 `（待定）` / `—` 占位；具体型号、单价、概率、档位**本轮不写**，先登记【待确认】。
实物奖池预算只定量级；虚拟礼包向{{SERVER_LINE_B}}申请、预留 4~5 个格子。

## 四、用户路径流程图

> **硬规矩（{{OWNER_ROLE}} {{AS_OF_DATE}} 定）：纯方案 md 里的用户路径一律用「纯文本树状流程」。**
> - **形式**：一个不带语言标记的代码块（就是 ``` 纯文本），用 `→ │ ├─ └─` 画树状分支，按四类玩家分组。
> - **禁止**：Mermaid / `flowchart` / `classDef` 等「技术路线图」语法，任何需要渲染引擎才能看的图；不主动往正文加可视化泳道大图、配色图例、独立 HTML 大图。
> - **不要附加段**：流程图上下不写「一句话读图」「三个关键卡点」「另附大图」这类讲解块；要交代的口径（闸门 / 归属 / 上限）直接写进树状节点或末尾 `★` 注里。
> - **为什么**：第历次迭代曾主动上 Mermaid + 独立泳道大图，被要求整段回退成纯文本——「换回之前那种形式即可，不用技术路线图」。朴素、能直接读的文本树才是这类方案要的。花活大图只在经验证点名要时另出、且不进正文。
> - 页面设计图那条线不受此限（那是玩家可见交互件，HTML 零外链），两回事别混。

按**四类玩家分组**写纯文本树状流程。下面是**形式示例，节点内容一律以当期纯方案第四章为准**，不得当成全局规定：

```
进入活动页 →【首屏：福利全部前置，进页即领（大奖钩子高亮）】
  → 登录授权 → 身份判断（{{四类按账号判定，可各自叠加下列任务线}}）
     ├─【全员通用线】{{签到 / 任务清单}} → 领抽奖机会 → {{统一奖池}}
     ├─【新用户线】{{下载创角}} → {{创角礼 + 自带机会 + 抽奖次数}}
     ├─【老玩家线】{{邀新（接新用户线）/ 组队阶梯（档数按当期）}}
     └─【回归用户线】{{定向入口}} → {{回归专属礼}} → 回全员通用线
  → 领奖（虚拟邮件 / 实物填收件信息）→ 版本情报 → 进入游戏
```

**归属推导、去重口径、次数上限**都在这里写清；页面设计图里不重复。流程图与对应参考文档口径节必须一致。**对齐裁决**：页面 vs 方案冲突时以纯方案为准；有意差异（页面占位 vs 方案确定值、预算脱敏、流程图不进页面）登记保留，不算矛盾（实践验证）。

## 验收（纯方案维度）

- 仅 4 个 H2；概述恰 5 个加粗 bullet；活动时间无具体日期；核心目标 ≤2 个。
- 任务表列名逐字一致；备注列零润色句、零句号结尾情绪句；润色句都在括号注里。
- 奖品六列表数据行全占位；无型号 / 单价 / 概率定值。
- 第四章流程图是**纯文本树状代码块**：四类玩家分组；`mermaid` / `flowchart` / `classDef` / 语言标记零命中；无可视化大图引用、无「一句话读图 / 关键卡点」附加段。
- 正文无「待确认 / 【内部资料】/ 出处 / 验收 / DDL / 工具调研 / @人」。
- 版本背景 ≤2 句、无年数 / 具体剧情 / 日期；未新增章节。
- 禁词 grep 零命中：`{{FORBIDDEN_TERM}}` / 付费变强 / 氪金碾压 / {{SERVER_LINE_A}}术语 / 具体日期 / 具体奖品 / 社群禁用梗。
- 「预约」按**语义**判定：允许作人群指代，禁的是当包装名 / 机制词 / 防御性规则。
- 流程图与**当期纯方案第四章**一致；示例树只作形式、节点不得写成全局规定；有意差异（占位 / 脱敏）登记保留。
