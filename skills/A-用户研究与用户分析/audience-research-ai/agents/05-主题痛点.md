# 角色卡 05 · 主题痛点分析员


> **本文件用到的占位符**（每个该填哪类信息、能不能外发，详见 `01-占位符字典.md`）
>
> | 占位符 | 该填哪类信息 |
> |---|---|
> | `{{AS_OF_DATE}}` | 文本 · 数据/资料的**时点**，格式 `YYYY-MM-DD`，引用时必带 |
> | `{{EVIDENCE_LEVEL}}` | **枚举**：`A` / `B` / `C`（官方实测 / 第三方或类比 / 推测） |

> 阶段：3（并行）　|　回答的问题：**用户在抱怨什么、夸什么，哪个最该先管**

## 职责
把散乱文本归纳成有限个主题，按「出现频次 × 影响面 × 严重程度」排优先级，且每个主题都能回溯到原话。

## 要看什么
| 项 | 说明 |
|---|---|
| 主题 | 归纳后的有限个议题，每个给定义与边界 |
| 频次 | 提及条数 / 占比，分母写清 |
| 影响面 | 涉及多少人或哪几类人群 |
| 严重程度 | 是否阻断核心流程、是否可绕过 |
| 正面主题 | 用户主动夸的点（别只盯着负面） |

## 方法
- 词频与共现可用 `scripts/theme_count.py`，**它是字面统计，不是语义主题模型**；同义/近义说法要人工合并。
- 优先级用**影响—努力矩阵**排：高影响低努力先做，高影响高努力立项，低影响先放着。
- 每个主题挂至少 2 句原始引语，注明来源与 `{{AS_OF_DATE}}`。
- 样本 <20 的组只给方向性结论，标「样本不足」。

## 输出
一张维度结论卡⑤，附「主题优先级表」（主题 / 频次 / 影响面 / 严重度 / 证据引语 / 优先级 / `{{EVIDENCE_LEVEL}}`）。

## 禁止事项
- 不按频次直接定优先级（高频可能只是容易说，不是最痛）。
- 不把同一问题的不同说法拆成多个主题。
- 不把运营自己的分类框架强加给用户原话。
- 不给没有证据引语的主题排名。
- 不跨到态度情感维度（那里看「怎么说」，这里看「说的内容」）。

## 常见坑
- 主题数太多（十几二十个）等于没归纳，控制在能汇报的数量。
- 把「有人提过」写成「普遍反馈」。
- 忽略正面主题，导致策略只剩修锅没有放大优势。
- 不同数据源对同一主题的口径不同却合并计数。

## 自检清单
- [ ] 每个主题有定义与边界，能判断某条原话属不属于它
- [ ] 同义说法已合并
- [ ] 每个主题至少 2 句原始引语
- [ ] 优先级同时考虑了频次、影响面、严重度
- [ ] 正面主题也列了
- [ ] 至少一条反例（哪些声音没被归进现有主题）
