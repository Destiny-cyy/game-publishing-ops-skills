# 参考 02 · 六维分析框架


> **本文件用到的占位符**（每个该填哪类信息、能不能外发，详见 `01-占位符字典.md`）
>
> | 占位符 | 该填哪类信息 |
> |---|---|
> | `{{AS_OF_DATE}}` | 文本 · 数据/资料的**时点**，格式 `YYYY-MM-DD`，引用时必带 |
> | `{{SAMPLE_N}}` | 整数 · 有效样本量，须带口径 |
> | `{{SENTIMENT_LEXICON_FILE}}` | 路径 · 情感 / 主题词典文件名（脚本用） |
> | `{{TOUCHPOINT}}` | 文本 · 真实存在、可被触达的**用户触点**名 |

> 六个维度**各由独立智能体负责**，但交的是同一张结论卡。
> 每维给：核心问题 / 要问什么 / 方法 / 指标 / 证据 / 常见坑 / 可运营抓手。
> 角色卡的「禁止事项」优先于本框架；证据纪律见 `04-证据等级与归因纪律.md`。

---

## 维度 ① 基础画像 —— 是谁

| 项 | 内容 |
|---|---|
| 核心问题 | 这批样本里的人，在服线、设备、来源、资历上怎么分布？ |
| 要问 | 哪条服线？什么终端？从哪来？新账号还是老账号？数据里有没有这些字段？ |
| 方法 | 频次分布 + 交叉表；缺失单独计一类 |
| 指标 | 各字段占比、交叉占比（分母必须写明） |
| 证据 | 结构化字段统计 + 能佐证的原话 |
| 抓手 | 决定触达渠道、素材语言、先做哪条服线 |

**常见坑**：把发声的人当全体用户（声量≠人口）；合并口径不同的样本；缺失值当 0；服线混淆（硬红线）。

## 维度 ② 行为分群 —— 怎么用

| 项 | 内容 |
|---|---|
| 核心问题 | 按行为能分成几群？每群多大、判据是什么？ |
| 要问 | 多久来一次？最近一次距今多久？处于生命周期哪一段？有没有可比较的价值代理字段？ |
| 方法 | 分位数式轻量分层（近似 RFM：最近一次 / 频次 / 价值），再交叉成群 |
| 指标 | 每群样本量、占比、典型行为；留存只在有数据时算 |
| 证据 | 行为日志或可核验的行为字段；`scripts/segment.py` |
| 抓手 | 决定定向人群、召回优先级、任务难度分档 |

**常见坑**：按讨论声量分群；一次行为当长期特征；存活者偏差；分群数超出 `{{SAMPLE_N}}` 能支撑的粒度；把「沉默」写成「流失」。

> 判据必须可复算：别人拿同一份数据、同一套切分点，应得到同样的群。

---

## 维度 ③ 需求动机 —— 要什么

| 项 | 内容 |
|---|---|
| 核心问题 | 用户想完成什么任务？卡在哪？愿意拿什么换？ |
| 要问 | 在什么情境下想达成什么？现在付出什么代价？放弃了什么？说了的和做的是否一致？ |
| 方法 | 原话编码 + JTBD 句式「当我 ___ 时，我想要 ___，以便 ___」；行为证据优先 |
| 指标 | 每条需求的支撑引语数 / 涉及人数，不拿词频冒充重要度 |
| 证据 | 原始引语（带来源与 `{{AS_OF_DATE}}`）+ 行为记录 |
| 抓手 | 决定内容主题、机制卖点、功能/流程改进的优先顺序 |

**常见坑**：把用户提的解决方案当需求；高频词当重要需求；被引导式提问带出来的需求当自发需求；需求写得抽象到无法指导动作（「想要更好的体验」）。

## 维度 ④ 态度情感 —— 怎么说

| 项 | 内容 |
|---|---|
| 核心问题 | 情绪与口碑往哪走？争议点和社区敏感点在哪？ |
| 要问 | 正/中/负各多少？随时间怎么变？哪几个议题正反双方都在说？哪些表述 community 明确反感？ |
| 方法 | 词典法（`scripts/sentiment_lexicon.py`，词典填 `{{SENTIMENT_LEXICON_FILE}}`）+ 人工复核反讽/黑话；争议按议题聚合 |
| 指标 | 情绪条数与占比（注明「讨论声量」口径）、争议议题清单 |
| 证据 | 正反双方原话、时点、来源 |
| 抓手 | 决定沟通语气、口径、红线规避、客服/社区应答重点 |

**常见坑**：情绪强度当人数；负面一律当风险；热评偏高赞拉偏整体；跨节点（预约期 vs 版本周）比情绪；把词典法结果当真实态度。

> 结论里必须写明方法局限：**词典法只反映字面，不等于真实态度**。

## 维度 ⑤ 主题痛点 —— 在抱怨 / 夸什么

| 项 | 内容 |
|---|---|
| 核心问题 | 归纳出哪几个主题？哪个最该先管？ |
| 要问 | 反复出现什么？涉及多少人？会不会阻断核心流程？有没有能绕过的办法？用户主动夸了什么？ |
| 方法 | 词频与共现（`scripts/theme_count.py`，需人工合并同义说法）+ 影响—努力矩阵排优先级 |
| 指标 | 主题频次、影响面、严重度、优先级 |
| 证据 | 每个主题至少 2 句原始引语 |
| 抓手 | 决定先修什么、放大什么优势、给 `content-brief` 供选题 |

**常见坑**：只按频次定优先级；同一问题的不同说法拆成多个主题；把运营自己的分类强加给原话；主题多到没法汇报；忽略正面主题。

> 样本 <20 的组只给方向性结论并标「样本不足」。

## 维度 ⑥ 旅程触点 —— 在哪卡住

| 项 | 内容 |
|---|---|
| 核心问题 | 从听说到完成关键动作，哪一步掉得多？哪个触点真的能触达？ |
| 要问 | 旅程分几阶段？每阶段的入口/动作/期望结果是什么？有没有埋点能回传？节点性质决定终点是什么？ |
| 方法 | 逐阶段列「入口 / 动作 / 可观测指标 / 有无埋点 / 断点」；断点至少给两个可能原因 |
| 指标 | 各阶段可测算的转化（**没埋点就写「不可测算」**）、触点可触达性 |
| 证据 | 埋点数据或访谈/问卷原话（后者只能给方向性判断，标 C 级） |
| 抓手 | 决定任务前置、入口位置、埋点需求、策略官派任务时用哪个 `{{TOUCHPOINT}}` |

**常见坑**：「没数据」写成「没卡点」；给没埋点的触点硬算转化率；单因归罪；把点击当完成；预约期与版本周混淆；忽略社区里的种草/劝退环节。

## 六维之间的关系（别混）

| 容易混的一对 | 分界 |
|---|---|
| ① 画像 vs ② 分群 | 画像是「静态属性分布」，分群是「按行为切出来的可复算群组」 |
| ④ 态度 vs ⑤ 痛点 | 态度是「怎么说的（情绪/口气）」，痛点是「说的内容（议题）」 |
| ③ 需求 vs ⑤ 痛点 | 需求是「想去哪」，痛点是「现在挡着什么」 |
| ⑥ 旅程 vs ② 分群 | 旅程看「步骤与断点」，分群看「人群与规模」 |

## 贯穿校验（不属于某一维，由红队负责）
- **价值与潜力**：这结论指向的人群值不值得投入？有没有可运营性？
- **风险与合规**：有没有踩社区红线、事实可溯源、服线混淆、商业披露？

这两项不单独出卡，写进 `04-证据等级与归因纪律.md` 的红队十项必查里。
