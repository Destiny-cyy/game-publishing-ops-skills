## 一、调研方式

联网检索相关开源仓库与官方文档型 skill，并打开仓库页 / README 核对：开源许可证、维护状态、运行时依赖、可复用能力、适用边界。下表是核对后的结论；许可证与维护状态以各仓库当时页面为准，引用前建议复核最新版本。

## 三、三方案对比结论

| 方案 | 判断 |
|---|---|
| **直接使用**某个现成 skill | ❌ 现成方案只覆盖传统定性研究，缺「多维分析结果 / 洞察转策略 / 多智能体 / 可迁移」四项能力 |
| **基于现成项目改造** | ⚠️ 会引入外部模型接口、重量运行时或传染性许可证，破坏本包「零依赖、可迁移、脱敏」的底线 |
| **借鉴骨架自主开发**（本包采用） | ✅ 借方法论章节 + 角色卡范式，自己写一套纯 Markdown 工作流；零依赖、平台无关、不碰任何账号密钥 |

**一句话**：现成的轮子分两类——「一份说明书」和「一套要装环境的程序」。本包只搬说明书里的**方法**，不搬程序。

---

## 四、三条不可退让的底线

1. **零第三方依赖、可迁移**：主工作流是纯 Markdown；`scripts/` 只用 Python 标准库，换台机器也能跑。
2. **不碰外部账号 / 密钥 / 接口**：所有「AI 干活」都由当前对话里的智能体按角色卡完成；合成用户、批量模拟不在本包能力范围内，需要时须另行评估与授权。
3. **不引入传染性许可证代码**：AGPL 类项目只作思路参考，包内不含其任何代码。

## 五、如果你要进一步引入这些项目

- 自行复核目标仓库的**当前**许可证、维护状态与依赖清单，别照抄本文件的时点结论。
- Apache-2.0 / MIT 相对宽松，通常保留版权声明即可；**AGPL 类有传染性**，商用或分发前请单独评估。
- 引入外部模型接口前，先确认你所在环境的账号与授权规则；本包默认不提供、也不要求。
- 引用第三方参考值（如人群分层参考区间）必须标来源、时点与 `{{EVIDENCE_LEVEL}}`，且只作参照、不作验收阈值。
