# 参考 01 · 六阶段工作流（每步的输入 / 产出 / 停止条件 / 验收）


> **本文件用到的占位符**（每个该填哪类信息、能不能外发，详见 `01-占位符字典.md`）
>
> | 占位符 | 该填哪类信息 |
> |---|---|
> | `{{ACTIVITY_WINDOW}}` | 文本 · 活动起止或持续天数 |
> | `{{AS_OF_DATE}}` | 文本 · 数据/资料的**时点**，格式 `YYYY-MM-DD`，引用时必带 |
> | `{{CONFIDENCE_LEVEL}}` | **枚举**：`高` / `中` / `低`，结论置信度；须写明受什么影响 |
> | `{{DATA_GAP}}` | 文本 · 明确声明**缺失的数据类别**及影响；**不许编数据补空** |
> | `{{EVIDENCE_LEVEL}}` | **枚举**：`A` / `B` / `C`（官方实测 / 第三方或类比 / 推测） |
> | `{{NODE_TYPE}}` | **枚举**：`预约期` / `版本上线周` / `长线运营期` 三选一。它决定整套方法论走哪条分支 |
> | `{{RESEARCH_QUESTION}}` | 文本 · 本次研究要回答的**核心疑问句**，必须能被数据证伪 |
> | `{{SAMPLE_N}}` | 整数 · 有效样本量，须带口径 |
> | `{{SERVER_LINE_A}}` | 文本 · 主服线名称 |
> | `{{STRATEGY_TIER}}` | **枚举**：`可立即执行` / `需验证` / `仅观测`，策略三档 |

> 顺序不能跳。返工几乎都不是因为写错，而是**开始得太早**。
> 规则总纲见 `SKILL.md`，本文件是执行细则。护栏全程生效：`_shared/REDLINES.md` 与本目录 `04-证据等级与归因纪律.md`。

## 全局约定
- 每个阶段的产出都是 `templates/交付物模板集.md` 里的一张表，**不写自由发挥的长文**。
- 阶段放行由主持人决定，每次都写「放行 / 退回 + 理由」。
- 任一阶段命中硬红线，整阶段不放行，退回上一阶段。

---

### 阶段 1 · 定题与口径

| 项 | 内容 |
|---|---|
| 目标 | 把模糊诉求收敛成一句可证伪的研究问题 |
| 输入 | 业务诉求、版本/活动事实、已有材料清单 |
| 产出 | 研究任务书（表一） |
| 负责 | 主持人 |

**动作**
1. 写 `{{RESEARCH_QUESTION}}`：一句疑问句，能被手上的数据证伪。
   - 反例：「了解用户需求」（不可证伪）。
   - 正例：「预约期里，哪一类触点对新进用户的入库完成率影响最大？」
2. 确认事实锚点：`{{NODE_TYPE}}`、`{{SERVER_LINE_A}}`、`{{ACTIVITY_WINDOW}}`、版本是否已上线。
3. 写研究边界：纳入谁 / 排除谁 / 时间范围 / **这次不回答什么**（防范围膨胀）。
4. 预设「数据不够时最多退到什么结论」，避免后面硬凑。

**停止条件**：研究问题不是疑问句；节点性质未确认；服线可能混淆。
**验收**：一句问题 + 三个锚点 + 边界 + 不回答清单，四项齐全。
**常见返工**：把「做个用户研究」当研究问题；把版本周当预约期（预约期素材不得写「版本已上线 / 现已开放 / 全新版本」）。

### 阶段 2 · 取数与清洗

| 项 | 内容 |
|---|---|
| 目标 | 四类数据统一入场，口径与缺口可查 |
| 输入 | 评论/帖子、问卷、访谈纪要、行为日志 |
| 产出 | 样本台账（表二） |
| 负责 | 主持人（可用 `scripts/data_contract.py`） |

**动作**
1. 四类数据各过一遍 `03-数据入场检查表.md`，登记「有 / 无 / 样本量 / 时点 / 来源」。
2. 统一成标准记录格式，去重、缺失单独计一类（**不当 0**）。
3. 写 `{{SAMPLE_N}}`，并说明它是「记录行数」还是「去重后人数」——这两个口径不能混。
4. 缺哪类就写 `{{DATA_GAP}}`，并写明「因此哪些维度只能给方向性结论」。

**停止条件**：没写清来源/时点/样本量；缺口未声明；不同来源口径未对齐就合并。
**验收**：四类逐项登记 + 统一记录格式 + 缺口声明 + 清洗规则留痕。
**常见返工**：把投放记录行数当成唯一用户数；把两个服线的样本合并后算总占比。

### 阶段 3 · 多维并行分析

| 项 | 内容 |
|---|---|
| 目标 | 六个维度各出一张**字段一致**的结论卡 |
| 输入 | 同一份样本台账 + 各自 `02-六维分析框架.md` 章节 + 对应角色卡 |
| 产出 | 6 张维度结论卡（表三） |
| 负责 | 6 个维度分析员（**并行**） |

**动作**
1. 主持人按 `06-多智能体调度.md` 的契约派发：每个分析员只拿自己的角色卡 + 同一份台账。
2. 各自按 `02-六维分析框架.md` 的方法分析，需要统计时跑 `scripts/` 里的对应工具。
3. 每卡六字段缺一不可：结论 / 证据 / `{{EVIDENCE_LEVEL}}` / `{{CONFIDENCE_LEVEL}}` / 可运营抓手 / 反例与例外。
4. 数据不足的维度：**写「无证据，仅假设」并标 C 级**，不许编。

**停止条件**：任一卡缺「证据」或「证据等级」；分析员跨维度下结论；把声量写成人口比例。
**验收**：6 张卡字段齐全 + 每卡至少一条反例 + 抓手只给方向没写完整策略。
**常见返工**：六个分析员各读了不同版本的样本；把结论写成了「用户比较活跃」这类空话。

### 阶段 4 · 交叉校验

| 项 | 内容 |
|---|---|
| 目标 | 把六张卡当待证伪的稿子逐条攻击 |
| 输入 | 6 张结论卡 |
| 产出 | 证据等级表（表四）+ 退回意见清单 |
| 负责 | 红队审查员（**串行，在汇总之后**） |

**动作**
1. 按 `agents/07-红队审查.md` 的十项必查逐项过。
2. 矛盾结论打回相关分析员对齐；对齐不了升级主持人裁决。
3. 证据不足的降为 C 级假设**保留并标注**，不悄悄抹掉。
4. 命中硬红线立即阻断，整阶段不放行。

**停止条件**：存在未对齐的矛盾；有结论没标证据等级；命中红线未处置。
**验收**：十项必查逐项有「通过 / 退回」结论；每条退回指定责任角色；红队未代写结论。
**常见返工**：红队自己把结论改了（责任不清，下次还会错）；为了赶进度放水。

### 阶段 5 · 洞察转策略

| 项 | 内容 |
|---|---|
| 目标 | 每条洞察变成可追溯、可验证的运营动作 |
| 输入 | 校验后的结论卡（每条带编号） |
| 产出 | 策略清单（表五） |
| 负责 | 策略官（可用 `scripts/strategy_lint.py` 体检） |

**动作**
1. 挑出「可运营抓手」非空的条目，编号。
2. 按 `05-洞察转策略规则.md` 映射成五元组：`人群 × 触点 × 内容/机制 × 时机 × 指标`。
3. 标 `{{STRATEGY_TIER}}` 三档，补「依据编号 + 预期指标 + 验证方式 + 红线检查结论」。
4. 跑策略体检：五元组缺项 / 三档未标 / 命中红线词，一律不通过。

**停止条件**：任一策略缺五元组任一元素；没标三档；C 级推测写成「可立即执行」；触点不存在。
**验收**：每条可追溯到洞察编号 + 指标写了分母和谁算 + 体检无阻断项。
**常见返工**：一条策略塞三个人群导致无法归因；把不能埋点的跳转写进 KPI。

### 阶段 6 · 出稿与跟踪

| 项 | 内容 |
|---|---|
| 目标 | 收成一份能被追问的结案报告 + 可回填的验证看板 |
| 输入 | 全部交付物 |
| 产出 | 结案报告（表六骨架）+ 验证看板 |
| 负责 | 报告官 |

**动作**
1. 按 `agents/09-报告官.md` 的固定七节成文，结论卡与策略清单**原样贴**，不润色。
2. 每个数字带来源、`{{AS_OF_DATE}}`、分母、`{{EVIDENCE_LEVEL}}`。
3. 验证看板写清每条策略的指标、观测窗口、当前状态、下期怎么回填基线。
4. 出外发版：按包根 `02-脱敏对照与使用边界.md` 脱敏，HTML 自包含。

**停止条件**：报告里出现无出处数字；外发版未脱敏；收尾写「继续观察」而无决策。
**验收**：七节齐全 + 每节能回答「这数怎么来的」 + 收尾写明下期动作与验证窗口。
**常见返工**：速览里把 C 级假设写成确定结论；把预算/内部 KPI 拆解带进外发版。

---

## 阶段拓扑一览

```
1 定题 → 2 取数 → 3 六维并行 ┐
                              ├→ 4 红队（串行）→ 5 策略官 → 6 报告官
        六个分析员同时开工 ┘
```

- **可并行**：阶段 3 的六个分析员。
- **必须串行**：4（汇总后）→ 5 → 6。
- **全程护栏**：主持人 + `_shared/REDLINES.md`，任何阶段可叫停。
