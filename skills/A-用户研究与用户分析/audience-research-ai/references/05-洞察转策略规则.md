# 参考 05 · 洞察转策略规则（五元组 / 三档 / 红线）


> **本文件用到的占位符**（每个该填哪类信息、能不能外发，详见 `01-占位符字典.md`）
>
> | 占位符 | 该填哪类信息 |
> |---|---|
> | `{{ACTIVITY_WINDOW}}` | 文本 · 活动起止或持续天数 |
> | `{{EVIDENCE_LEVEL}}` | **枚举**：`A` / `B` / `C`（官方实测 / 第三方或类比 / 推测） |
> | `{{GAME_FACT_COMMUNITY_VOICE}}` | 文本 · 社区对官方口吻/事实错误的敏感点 |
> | `{{NODE_TYPE}}` | **枚举**：`预约期` / `版本上线周` / `长线运营期` 三选一。它决定整套方法论走哪条分支 |
> | `{{PAY_TO_WIN_WORD_1}}` | 文本 · 本游戏里「付费变强」类违规表述词 |
> | `{{SEGMENT_LABEL}}` | 文本 · 人群分群的**中性命名**或命名规则，不带褒贬 |
> | `{{SERVER_LINE_A}}` | 文本 · 主服线名称 |
> | `{{SERVER_LINE_B}}` | 文本 · 另一条服线名称。**两条服线的信息不可混用**是硬红线 |
> | `{{STRATEGY_TIER}}` | **枚举**：`可立即执行` / `需验证` / `仅观测`，策略三档 |
> | `{{TOUCHPOINT}}` | 文本 · 真实存在、可被触达的**用户触点**名 |

> 这一份是「智能」和「胡编」的分界线：AI 可以帮你想策略，但每条都要能追溯回某张结论卡、能被一个指标验证。
> 策略官必读；`scripts/strategy_lint.py` 是本规则的机械实现。

---

## 一、固定映射

```
每条洞察（带编号） → 人群 × 触点 × 内容/机制 × 时机 × 指标
```

**只允许从「校验后、可运营抓手非空」的结论卡出发**。红队标为 C 级假设的条目只能进「需验证」或「仅观测」。

### 逐元素定义

| 元素 | 必须写什么 | 不合格写法 → 合格写法 |
|---|---|---|
| **人群** | 结论卡编号 / 分群名，指向一个明确群组 | 「广大玩家」→「卡②·成长群（`{{SEGMENT_LABEL}}`）」 |
| **触点** | `{{TOUCHPOINT}}`，且必须来自旅程触点卡里「真实存在且可触达」的项 | 「全渠道」→「加速页首屏 bn」 |
| **内容/机制** | 一个具体动作，含对象与变化 | 「加强引导」→「把入库任务从第三屏提到首屏，并加一句说明」 |
| **时机** | 对齐 `{{NODE_TYPE}}` 与 `{{ACTIVITY_WINDOW}}`，写清起止或阶段 | 「尽快」→「{{ACTIVITY_WINDOW}} 内首三日」 |
| **指标** | 指标名 + 谁算 + 分母 + 目标值 + `{{EVIDENCE_LEVEL}}` | 「提升转化」→「入库完成率＝完成入库人数 ÷ 活动参与人数，目标 {{目标值}}（B 级）」 |

### 每条策略还必须带四个附加字段
1. **依据的洞察编号**（没有编号的策略一律删掉）
2. **预期指标**（与五元组里的指标一致）
3. **验证方式**（怎么算过：看哪个数、观测窗口多长、阈值是什么）
4. **红线检查结论**（逐项过下面的清单，写「通过」或命中了哪条）

## 二、三档 `{{STRATEGY_TIER}}`

| 档 | 含义 | 准入门槛 | 典型处置 |
|---|---|---|---|
| **可立即执行** | 这期就做 | 依据 A/B 级 + 触点可触达 + 指标可回传 + 红线全过 | 排进活动任务链，回填验证看板 |
| **需验证** | 先小范围试 | 依据 B/C 级，或指标需先补埋点 | 定小流量/短窗口试验，明确通过阈值 |
| **仅观测** | 只看不做 | 依据 C 级，或触点/口径尚未确认 | 只记数据，不写进 KPI，不派任务 |

**硬门槛**
- C 级推测**不得**进「可立即执行」。
- 不能埋点的动作（尤其跳转类）一律降为「仅观测」，**不写进 KPI**。
- 触点不存在的渠道不派任务：**渠道能给什么，才派什么**。

## 三、红线检查清单（逐条打勾）

- [ ] 没有「付费变强 / 氪金碾压 / 战力领先」类表述（对照 `{{PAY_TO_WIN_WORD_1}}`）
- [ ] 没有官方居高临下口吻（对照 `{{GAME_FACT_COMMUNITY_VOICE}}`）
- [ ] 服线信息没有混淆（`{{SERVER_LINE_A}}` / `{{SERVER_LINE_B}}`）
- [ ] 预约期没有写「版本已上线 / 现已开放 / 全新版本」
- [ ] 没有承诺付费包名、付费货币、绝版/限定物品、数据互通、跨服继承
- [ ] 创作者/达人合作已标注商业披露
- [ ] 数字都带出处、时点、口径、证据等级
- [ ] 外发版不含预算、内部 KPI 拆解、权重排序、文档 ID、本机路径
- [ ] 指标口径可与 `_shared/口径模板.md` 对上

命中任一硬红线 → 策略体检不通过，退回策略官。

## 四、策略体检（`strategy_lint.py`）

输入是一张 CSV，列名固定（见 `scripts/README.md`）：

```
id, insight_id, audience, touchpoint, action, timing, metric, metric_denominator,
evidence_level, tier, expected, validation, redline_check
```

脚本机械检查：
1. 五元组对应列非空；
2. `tier` 是三档枚举之一；
3. `insight_id` 非空且能对应结论卡编号；
4. `evidence_level` 为 C 时 `tier` 不得是「可立即执行」；
5. `action` / `timing` 文本命中红线词表则报错；
6. 输出 `lint.json`：通过条数、阻断项、逐条原因。

> 脚本只查**结构与词表**，查不了语义和事实。红队与人工复核仍然必需。

## 五、验证方式模板

```
验证方式：
  看哪个数：{{指标名}}
  谁回传：{{渠道/系统}}
  观测窗口：{{起止或天数}}
  通过阈值：{{数值或相对变化，带证据等级}}
  不通过怎么办：降档 / 停用 / 转为仅观测
  下期回填：把实际值写进 _shared/口径模板.md 对应基线行
```

## 六、常见坑

| 坑 | 后果 |
|---|---|
| 一条策略塞三个人群 | 结果无法归因，等于没验证 |
| 指标只写「提升转化率」 | 分母和谁算都不知道，无法复算 |
| 策略数量远超执行能力 | 最后一条都没验证，报告变成许愿清单 |
| 把观测项写进 KPI | 不能埋点却背目标，结案时必然说不清 |
| 用「持续优化」收尾 | 没有决策，等于回到拍脑袋 |
| 直接把结论卡原文当策略 | 结论是「是什么」，策略是「做什么」，两回事 |
