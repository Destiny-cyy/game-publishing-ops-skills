# AI 用户研究与智能运营策略（多智能体版）

**一句话**：把「一堆散乱的用户材料」变成「六个维度、带证据、能核对的分析结果」，再自动变成「有人群、有触点、有指标、能验证」的运营策略清单。

**和 `audience-insight` 的关系（并列，不重叠）**

| | `audience-insight` | 本 skill |
|---|---|---|
| 定位 | **采集与聚类**：把公开讨论爬下来、跑 TF-IDF+KMeans，出人群画像 | **研究与策略**：不负责采集，负责怎么问、怎么分维度、怎么校验、怎么把洞察变成策略 |
| 输入 | 平台公开评论/帖子 | 任意来源：已有的聚类结果、问卷、访谈纪要、评论导出、行为日志 |
| 产出 | 聚类结果 + HTML 洞察报告 | 研究任务书、六维结论卡、证据等级表、策略清单、结案报告 |
| 谁先谁后 | 可以先跑它拿原始人群事实 | 再跑本 skill 做结构化研究与策略；也可独立使用（自带轻量脚本处理本地数据） |

两者**互相引用、不重复维护同一份内容**：人群事实以 `audience-insight` 的原始聚类字段为准，本 skill 只做解读与策略，不改写它的数字。

## 一、什么时候用 / 什么时候不用

**用**：要搞清用户是谁、要什么、为什么流失、在哪卡住；要把访谈/问卷/评论整理成能汇报的结论；要从用户结论推导运营动作；想让多个智能体分工并行推进一次研究。

**不用**：只要一个数字看板或埋点报表（那是数据平台的事）；只要爬数据（用 `audience-insight`）；要出一版完整渠道方案（研究完成后交给 `channel-context` → `channel-selection` → `channel-plan`）。

**开工前必问三件事**（顺序不能跳，返工几乎都因为开始得太早）：
1. **研究问题**：这次到底要回答哪一句疑问句？`{{RESEARCH_QUESTION}}`
2. **节点与事实锚点**：`{{NODE_TYPE}}`、`{{SERVER_LINE_A}}`、`{{ACTIVITY_WINDOW}}`、版本是否已上线。
3. **手上有什么数据**：四类数据（评论/帖子、问卷、访谈纪要、行为日志）各有多少、`{{SAMPLE_N}}` 是多少、缺哪类。

## 二、六阶段工作流（清晰主干，顺序不能跳）

详细到「每步输入 / 产出 / 停止条件 / 验收」见 `references/01-六阶段工作流.md`。这里只给主干：

| 阶段 | 主持的智能体 | 输入 | 产出 | 不达成就停 |
|---|---|---|---|---|
| 1 定题与口径 | 主持人 | 业务诉求、事实锚点 | **研究任务书** | 研究问题写不成一句疑问句 / 节点性质没确认 |
| 2 取数与清洗 | 主持人 + 数据入场检查表 | 四类原始数据 | **样本台账** | 没写清数据来源、时点、样本量、缺口 |
| 3 多维并行分析 | 6 个维度分析员 | 样本台账 + 各自框架章节 | **6 张维度结论卡** | 任一卡缺「证据」或「证据等级」字段 |
| 4 交叉校验 | 红队审查员 | 6 张结论卡 | **证据等级表** | 存在互相矛盾未对齐 / 把声量写成人口比例 |
| 5 洞察转策略 | 策略官 | 校验后的结论 | **策略清单** | 任一策略缺五元组任一元素 / 没标三档 |
| 6 出稿与跟踪 | 报告官 | 全部交付物 | **结案报告 + 验证看板** | 报告里出现无出处的数字 / 外发版未脱敏 |

**贯穿全程的护栏**（任何阶段命中即退回）：社区红线、`{{EVIDENCE_LEVEL}}` 必须标、声量 ≠ 人口比例、不可比口径不相加、数据缺口必须明写不许编、人工复核。详见 `_shared/REDLINES.md` 与 `references/04-证据等级与归因纪律.md`。

## 三、10 个智能体角色卡（平台无关）

`agents/` 下每个文件是一张独立角色卡，包含「职责 / 输入 / 输出 / 禁止事项 / 自检清单」。**并行派发时，把对应那一张卡交给对应智能体即可**，主文档不依赖任何特定调度框架。

| 角色 | 文件 | 一句话职责 |
|---|---|---|
| 主持人 | `agents/00-主持人.md` | 拆任务、控进度、汇总、决定何时进入下一阶段 |
| 基础画像分析员 | `agents/01-基础画像.md` | 是谁：服线、设备、来源、人口与账号属性 |
| 行为分群分析员 | `agents/02-行为分群.md` | 怎么用：活跃、留存、生命周期、价值分层 |
| 需求动机分析员 | `agents/03-需求动机.md` | 要什么：目标、任务、JTBD、取舍 |
| 态度情感分析员 | `agents/04-态度情感.md` | 怎么说：情绪、口碑、争议点、敏感红线 |
| 主题痛点分析员 | `agents/05-主题痛点.md` | 在抱怨/夸什么：主题归纳、痛点优先级 |
| 旅程触点分析员 | `agents/06-旅程触点.md` | 在哪卡住：旅程图、漏斗、触点、转化断点 |
| 红队审查员 | `agents/07-红队审查.md` | 专挑刺：样本、口径、因果、红线、反例 |
| 策略官 | `agents/08-策略官.md` | 把洞察压成运营五元组，分三档，附验证方式 |
| 报告官 | `agents/09-报告官.md` | 分节成文、统一口径、可被追问、出外发版 |

**怎么真的用多个智能体推进**：见 `references/06-多智能体调度.md`。核心是一份「派发契约」——每个智能体只拿自己的卡 + 同一份样本台账，独立产卡，主持人汇总；红队与策略官串行在汇总之后。文档给的是平台无关的契约，另附一段「在本 AI 工作台里怎么并行派发」的说明。

## 四、六个维度的分析结果（统一结论卡）

每一维不是写一段漂亮话，而是交**同一张卡**（模板见 `templates/交付物模板集.md`），六个字段缺一不可：

| 字段 | 要求 |
|---|---|
| 结论 | 一句话，可证伪，不写「用户比较活跃」这种空话 |
| 证据 | 必须带原话、数据或数据出处；没有就写「无证据，仅假设」 |
| 证据等级 | `{{EVIDENCE_LEVEL}}`：A 官方实测 / B 第三方或类比 / C 推测 |
| 置信度 | `{{CONFIDENCE_LEVEL}}`：高 / 中 / 低，并说明受什么影响 |
| 可运营抓手 | 这一维能指向哪类动作（只给方向，不在此处写完整策略） |
| 反例与例外 | 至少一条反例或不适用边界，防止以偏概全 |

六维各自「问什么 / 用什么方法 / 看哪些指标 / 常见坑」见 `references/02-六维分析框架.md`。

**数据纪律**：四类数据各有一张「入场检查表」（`references/03-数据入场检查表.md`）。缺哪类就写 `{{DATA_GAP}}`，**不允许 AI 用推测补齐**；样本不足的组只给方向性结论并标「样本不足」；讨论声量不得写成人口比例。

## 五、智能运营策略：洞察 → 五元组 → 三档

策略官不允许自由发挥。每条洞察必须映射成一个**固定五元组**：

```
人群 × 触点 × 内容/机制 × 时机 × 指标
```

- **人群**：来自哪一维度结论卡（写卡编号，不写「广大玩家」）
- **触点**：`{{TOUCHPOINT}}`，必须是真实存在、能被触达的位置
- **内容/机制**：具体动作，且通过社区红线检查
- **时机**：对齐 `{{NODE_TYPE}}` 与 `{{ACTIVITY_WINDOW}}`；预约期不得写「版本已上线」
- **指标**：谁算、分母是什么、目标值带 `{{EVIDENCE_LEVEL}}`

每条策略再标 `{{STRATEGY_TIER}}` 三档之一：**可立即执行 / 需验证 / 仅观测**，并且必须写明「依据的洞察编号 + 预期指标 + 验证方式 + 红线检查结论」。完整规则与红线清单见 `references/05-洞察转策略规则.md`。

> 这一条是「智能」和「胡编」的分界线：AI 可以帮你想策略，但每条都要能被追溯回某张结论卡、能被一个指标验证。

## 六、可选轻量脚本（不联网、零第三方依赖）

`scripts/` 下是几个纯标准库小工具，**只做统计与体检，不做任何 AI 推理**（推理由对话里的智能体完成）：

| 脚本 | 干什么 | 对应阶段 |
|---|---|---|
| `data_contract.py` | 四类数据统一成标准记录、校验必填、去重、报缺口 | 2 |
| `segment.py` | 按字段做频次/交叉表、分位数式轻量分群 | 3 |
| `theme_count.py` | 主题词频与共现（词典法，非语义聚类） | 3 |
| `sentiment_lexicon.py` | 基于自填词典的情感倾向统计 | 3 |
| `strategy_lint.py` | 策略清单体检：五元组完整、三档、红线词 | 5 |
| `selftest.py` | 一键自测，用最小虚构样本跑通以上全部 | 验收 |

运行方式见 `scripts/README.md`。**默认解释器写 `{{PYTHON_ENV}}`**（换成你自己的解释器或虚拟环境），脚本本身不含任何绝对路径。

> 明确边界：这些脚本是“轻量替代”，不是重型语义主题模型，也不是真实情感模型。它们的价值是**把口径和算术固定下来**，判断仍由人/智能体做。借鉴来源与取舍见 `references/07-借鉴来源与许可证.md`。

## 八、交付前自检（七问，命中即退回）

1. 研究问题是不是一句可证伪的疑问句？
2. 每个数字有没有出处、时点、口径、`{{EVIDENCE_LEVEL}}`？
3. 六张结论卡有没有缺「证据 / 反例」字段？
4. 有没有把讨论声量写成「X% 的玩家」？
5. 矛盾结论对齐了吗？红队挑出的问题闭环了吗？
6. 每条策略的五元组齐不齐、三档标没标、能不能被一个指标验证？
7. 外发版脱敏了吗（预算、内部 KPI 拆解、文档 ID、本机路径）？

## 九、适用边界与免责

- 本 skill 是**方法与模板**，不含任何真实业务数据；填进去的数据由使用方负责。
- 合成用户 / 模拟访谈类输出只能当**假设**，必须经真实用户验证，不得直接当决策依据。
- 词典法情感与词频主题只反映字面，不等于真实态度；结论一律须人工复核。
- 不接入任何外部大模型账号、密钥或接口；需要批量模拟时应另行评估与授权。
- `{{...}}` 未替换前，模板与脚本**不能直接用于生产**。
