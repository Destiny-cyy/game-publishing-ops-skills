# audience-research-ai · 使用说明（人读版）


> **本文件用到的占位符**（每个该填哪类信息、能不能外发，详见 `01-占位符字典.md`）
>
> | 占位符 | 该填哪类信息 |
> |---|---|
> | `{{ACTIVITY_WINDOW}}` | 文本 · 活动起止或持续天数 |
> | `{{CONFIDENCE_LEVEL}}` | **枚举**：`高` / `中` / `低`，结论置信度；须写明受什么影响 |
> | `{{DATA_GAP}}` | 文本 · 明确声明**缺失的数据类别**及影响；**不许编数据补空** |
> | `{{NODE_TYPE}}` | **枚举**：`预约期` / `版本上线周` / `长线运营期` 三选一。它决定整套方法论走哪条分支 |
> | `{{PYTHON_ENV}}` | 路径 · 你的 Python 解释器或虚拟环境 |
> | `{{RESEARCH_QUESTION}}` | 文本 · 本次研究要回答的**核心疑问句**，必须能被数据证伪 |
> | `{{SENTIMENT_LEXICON_FILE}}` | 路径 · 情感 / 主题词典文件名（脚本用） |
> | `{{SERVER_LINE_A}}` | 文本 · 主服线名称 |
> | `{{STRATEGY_TIER}}` | **枚举**：`可立即执行` / `需验证` / `仅观测`，策略三档 |
> | `{{TOUCHPOINT}}` | 文本 · 真实存在、可被触达的**用户触点**名 |

> 一份**给人和 AI 一起用**的用户研究作业包：多智能体分工 → 六个维度的分析结果 → AI 把洞察变成可验证的运营策略。
> 全包脱敏，换游戏、换团队、换办公工具都能用；`SKILL.md` 是给 AI 读的作业指导书，本文件是给人读的说明。

## 1. 这套东西解决什么问题

常见的三种糟糕状态：

| 状态 | 后果 |
|---|---|
| 一堆评论/问卷/访谈纪要，读完了只会说「用户反馈还行」 | 没有结论，没法汇报 |
| AI 一口气写一份「用户洞察报告」，看着漂亮 | 每段都没证据、互相矛盾、不知道哪句能信 |
| 洞察有了，运营动作还是靠拍脑袋 | 研究和执行断成两截 |

这套 skill 用三件事把它们接起来：

1. **清晰工作流**：六阶段，每阶段有输入、产出、停止条件，不达标不许往下走。
2. **多维度分析结果**：六个维度各由独立智能体产出**同一张结论卡**（结论 / 证据 / 证据等级 / 置信度 / 抓手 / 反例），能横向对比、能汇总。
3. **智能运营策略**：每条洞察必须压成「人群 × 触点 × 内容/机制 × 时机 × 指标」五元组，分三档，附验证方式——AI 可以帮你想，但每条都能追溯、能被指标验证。

---

## 2. 和 `audience-insight` 怎么配合

包里 A 组下有两个 skill，**并列、不重叠**：

- `audience-insight`：**采集与聚类**。爬公开讨论、跑聚类、出人群画像（需要第三方依赖与浏览器内核，可选）。
- `audience-research-ai`：**研究与策略**。不负责采集，负责怎么问、怎么分维度、怎么校验、怎么把洞察变成策略（纯文档 + 可选轻量脚本）。

推荐顺序：先 `audience-insight` 拿原始人群事实 → 再本 skill 做结构化研究与策略。**也可以完全独立使用**：直接把问卷、访谈纪要、评论导出喂进来，用 `scripts/` 里的轻量工具处理。

## 3. 五步跑通第一个任务

1. **填占位符**：全包填值处是 `_shared/config.example.yaml`（复制成 `config.yaml`）。本 skill 额外用到 `{{RESEARCH_QUESTION}}`、`{{SEGMENT_LABEL}}`、`{{DATA_GAP}}`、`{{CONFIDENCE_LEVEL}}`、`{{STRATEGY_TIER}}`、`{{TOUCHPOINT}}`、`{{SENTIMENT_LEXICON_FILE}}`，含义查包根目录 `01-占位符字典.md` 的 H 组。
2. **写研究任务书**：打开 `templates/交付物模板集.md` 的第一张表，把研究问题写成一句可证伪的疑问句，写清 `{{NODE_TYPE}}`、`{{SERVER_LINE_A}}`、`{{ACTIVITY_WINDOW}}`。
3. **整理样本台账**：四类数据各过一遍 `references/03-数据入场检查表.md`，缺的写 `{{DATA_GAP}}`，不许补编。想跑脚本就用 `scripts/data_contract.py` 统一格式。
4. **派发智能体**：按 `references/06-多智能体调度.md` 的契约，把 6 张维度卡分别交给 6 个智能体；汇总后交红队，再交策略官。
5. **收口**：报告官按 `templates/交付物模板集.md` 的结案报告骨架成文；用 `scripts/strategy_lint.py` 体检策略清单；外发版按包根 `02-脱敏对照与使用边界.md` 处理。

> 只想快速看效果：直接读 `examples/虚构示例_六阶段走通.md`，用一款虚构游戏把六阶段完整走了一遍。

## 5. 10 张角色卡一览

| 角色 | 什么时候上场 | 交什么 |
|---|---|---|
| 主持人 | 全程 | 研究任务书、阶段推进决定、汇总 |
| 基础画像分析员 | 阶段 3 并行 | 维度结论卡① |
| 行为分群分析员 | 阶段 3 并行 | 维度结论卡② |
| 需求动机分析员 | 阶段 3 并行 | 维度结论卡③ |
| 态度情感分析员 | 阶段 3 并行 | 维度结论卡④ |
| 主题痛点分析员 | 阶段 3 并行 | 维度结论卡⑤ |
| 旅程触点分析员 | 阶段 3 并行 | 维度结论卡⑥ |

## 6. 六个维度分别看什么

| 维度 | 核心问题 | 典型证据 |
|---|---|---|
| 基础画像 | 是谁 | 服线、设备、来源、账号属性分布 |
| 行为分群 | 怎么用 | 活跃频次、留存、生命周期阶段、价值分层 |
| 需求动机 | 要什么 | 原话里的目标、任务、取舍（JTBD） |
| 态度情感 | 怎么说 | 情绪倾向、口碑、争议点、社区敏感词 |
| 主题痛点 | 在抱怨/夸什么 | 高频主题、痛点优先级、影响面 |
| 旅程触点 | 在哪卡住 | 关键触点、漏斗断点、流失位置 |

每维的完整框架（方法 / 指标 / 坑）见 `references/02-六维分析框架.md`。**六张卡字段完全一致**，这是能汇总、能对比、能被红队审查的前提。

## 7. 策略是怎么"智能"生成的

不是让 AI 自由发挥，而是三步固定映射：

1. 从校验后的结论卡里挑出「可运营抓手」非空的条目，每条给一个编号。
2. 每条映射成五元组：`人群 × 触点 × 内容/机制 × 时机 × 指标`（`{{TOUCHPOINT}}`、`{{NODE_TYPE}}`、`{{ACTIVITY_WINDOW}}` 从这里进来）。
3. 标 `{{STRATEGY_TIER}}`（可立即执行 / 需验证 / 仅观测），补上「依据编号 + 预期指标 + 验证方式 + 红线检查结论」。

`scripts/strategy_lint.py` 会机械检查五元组有没有缺项、三档有没有标、有没有命中红线词。**AI 负责想，脚本负责查，人负责拍板。**

## 8. 脚本：装什么、怎么跑

**依赖**：Python 3.10+，**只用标准库**（csv / json / statistics / collections / argparse / pathlib / re）。不需要 pip install 任何东西，不联网，不读任何绝对路径，不接任何账号或密钥。

默认解释器请按你的环境填 `{{PYTHON_ENV}}`（本包不预置任何本机路径）。下列示例用 `python` 代指你的默认解释器。

```bash
cd skills/A-用户研究与用户分析/audience-research-ai/scripts

python selftest.py                      # 先跑这个：一键自测，全部 PASS 才继续
python data_contract.py --input sample_data/comments.csv --out out/contract.json
python segment.py       --input sample_data/profiles.csv --by server_line --out out/segments.json
python theme_count.py   --input sample_data/comments.csv --lexicon sample_data/lexicon.csv --out out/themes.json
python sentiment_lexicon.py --input sample_data/comments.csv --lexicon sample_data/lexicon.csv --out out/sentiment.json
python strategy_lint.py --input sample_data/strategies.csv --out out/lint.json
```

输出统一是 JSON + 控制台摘要，方便交给智能体或人继续读。`scripts/README.md` 有每个脚本的字段说明。

**明确的能力边界**：词频主题 ≠ 语义主题模型，词典情感 ≠ 真实态度，分位数分群 ≠ 机器学习聚类。这些脚本只负责把**口径和算术固定下来**，判断仍由智能体和人做。想上语义模型请自行评估依赖与许可证（见 `references/07`）。

## 9. 借鉴了哪些开源项目

调研过公开的文档型 skill、多智能体模拟项目、多智能体框架与主题建模方法，逐一核过许可证、维护状态与依赖风险。结论是**只借方法论与角色分工范式，不搬一行代码**：因为现成项目要么绑定外部大模型接口，要么带传染性许可证，要么需要重量运行时，都会破坏本包“零依赖、可迁移、脱敏”的底线。

逐条出处与取舍见 `references/07-借鉴来源与许可证.md`。

## 10. 适用边界与免责

- 方法与模板，不含真实业务数据；填进去的数据由使用方自行负责。
- 合成用户 / 模拟访谈的输出只能当**假设**，须经真实用户验证，不得直接当决策依据。
- 词典法情感、词频主题、规则分群都只反映字面与统计，不等于真实态度或因果；结论一律人工复核。
- 不接入任何外部大模型账号、密钥或接口；如需批量模拟，须另行评估与授权。
- `{{...}}` 未替换前，模板与脚本**不能直接用于生产**；外发前按包根 `02-脱敏对照与使用边界.md` 检查。
- 采集公开内容仍须遵守目标平台条款与所在地法规（若配合 `audience-insight` 使用）。

## 11. 常见问题

**没有多智能体环境能用吗？** 能。角色卡是纯文字，一个 AI 按顺序扮演十个角色、逐张填卡，效果一样，只是慢一些。

**只有一堆评论，没有问卷和访谈怎么办？** 在样本台账里写 `{{DATA_GAP}}` 标明缺两类，只跑能支撑的维度；需求动机、旅程触点若证据不足，结论卡写「无证据，仅假设」并标 C 级，不要硬凑。

**脚本跑出来和 AI 判断不一致？** 以脚本的算术与口径为准，把「为什么不一致」写进红队意见，不要改数字去迁就结论。

**能直接生成一份完整运营方案吗？** 不能，也不该。本 skill 交的是**研究结论与策略清单**，完整方案交给 D 组的 `channel-context` → `channel-selection` → `channel-plan`。研究先于动作。
