# 发行节奏与执行计划

> 准则层唯一真源：`_shared/REDLINES.md` 第六章（执行与排期）。本 skill 只管节奏骨架与时点，具体里程碑与风险条目以准则为准。

## 四层放行（借鉴 tarkaai/gtm-skills）

| 层级 | 目标 | 周期 | 放行条件 |
|---|---|---|---|
| **Smoke 试水** | 验证有人买账 | 1 周 | 出现明确正向信号，且无社区负面事件 |
| **Baseline 基线** | 证明可重复 | 2 周 | 连续两次稳定复现，数据口径已跑通 |
| **Scalable 放大** | 上量 5–10× | 2 个月 | 单位成本可控，供应链跟得上 |
| **Durable 常驻** | 变固定机制 | 6 个月+ | 已沉淀 SOP，可脱离个人驱动 |

**当前层没过阈值不许加码。** Smoke 没过不是失败，是信号——改人群、卖点或渠道，而不是加钱。

注：常规版本节点活动（{{CHANNEL_TYPE_A}}{{CHANNEL_COUNT}}家 + {{CHANNEL_E}}）已属 **Durable 层**——机制固定、每节点复用。
对新渠道（如网吧、内渠、新垂媒）才从 Smoke 起步。

## 三条硬前置

- **T-45：{{APPROVAL_PARTY}}审批。** CDK 配额与 CPS 上架需 {{APPROVAL_PARTY}}审批，是全盘最易卡住的环节。凡涉及 CDK，必须在 T-45 前启动申请，并留出"数据验证包"时间（上一节点{{CHANNEL_E}}数据 → 提交 {{DEVELOPER}} → 解锁下一批渠道）。
  - **已超期怎么办**：不要假装还能申请。明确写「本期只能使用现有库存」，并给出替代方案（加大现有 SKU 投放 / 用实物或渠道自有权益顶替）。超期还按"待审批"排期，等于把上线风险藏起来。
- **T-30：事实核对 + 资源位档期锁定。** ①所有数字、日期、机制改动对齐官方口径（红线 4）；②**热门资源位档期必须在 T-30 锁定**——版本上线日当天的客户端弹窗、首页 bn、push 必然被同日上线的游戏争抢，等到上线周再谈就没有位置了；③**向{{CHANNEL_COUNT}}家索取书面承诺曝光量与资源位清单**——结案时「曝光率＝实际÷承诺」，没有这个分母，履约验收无从计算；④**确认回归人群定向能力**（能否筛 30 天未加速用户），做不到就把回归目标降级为"单独报数、不作硬考核"。
- **内部排期口径 ≠ 对外事实。** 内部按排期日期推进没问题，但对外物料里的上线日期、版本内容发布前必须与 {{DEVELOPER}} 官方公告复核。官方未公布的内容不得以既定事实口吻写出。

## 标准节奏（以版本节点为 T0）

```
T-45  {{DEVELOPER}} 沟通：CDK 配额申请、CPS 上架申请（过此窗口只能用现有库存）
T-30  立项 + 事实核对 + 【热门资源位档期锁定】
T-21  奖品采购清单锁定（按既定四条约束，不再改价带）、CDK 到位的确认、到货拍照
T-14  素材与活动页就绪、各家活动配置提审
T-7   预热（倒计时位上线、社区铺垫、KOC 预告）
T-1   终检：CDK 导入、抽奖概率复核、版本日带宽预案
T0    版本上线：渠道活动【与版本日同步开跑】，不抢跑不延后
T+4   中期复核：CDK 核销率 → 解锁追加池；参与/加速环比/点击率对账
T+7   活动收口，5 个工作日内回收未核销 CDK 并更新库存表
T+30  复盘 → 决策 → 回写 context
```

**为什么卡在版本日（T0）**：版本上线周是全年唯一的自然流量峰值——玩家当天的固定动作是下载大更新包、登录、进新区、组队，{{CHANNEL_TYPE_A}}四件事全都能接，且都处在强意图场景。抢跑（还没内容可玩）或延后（热度已过）都会显著折损。

**版本日特有风险**：大更新包会挤占下载带宽 → 活动页首屏同时放「更新加速」与「一键入库」两个入口（不只服务新用户）；若渠道带宽紧张，把大尺寸动图降级为静态图。

**{{VERSION_NAME_HIST}} 实例参考**：某版本节点上线，文化主题外观同步上线，四渠道同日开启抽奖活动。
奖品采买 {{BUDGET_AMOUNT}}K / 469 件，预估参与 6 万+ / 曝光 {{KPI_REACH}}。

## 现实约束（排期时逐条确认）

- **{{PLATFORM_A}} 首帧轮播 T+1 数据延迟**，系统无法实时追加，不按时段切分量级 —— 按整档申请
- {{CHANNEL_TYPE_A}}、网吧、内渠的素材规格与提交截止时间各不相同，需逐家确认
- **PC 端渠道无法上架该平台游戏**，内渠需换形式（频道引流至社群）
- 委托 {{PLATFORM_DATA_TEAM}} 提取号码包时不能指定具体某款游戏的玩家
- 外团渗透野生群需走立项流程，只能半官方口径

## 输出结构

1. **一句话目标**：在〔时间段〕内，通过〔渠道组合〕，让〔人群〕产生〔可度量结果〕
2. **节奏表**：按上面的标准节奏，每节点写动作/负责人/产出物/依赖前置
3. **活动机制**：交给 `campaign-mechanic` 产出（任务链路 + 奖品包 + 预算）
4. **素材清单**：交给 `content-brief` 逐条产出
5. **责任矩阵**：谁决策/产出/审核/发布/盯数据。审核人必过 `../REDLINES.md` 自检七问
6. **预算**：只列本动作专属成本（奖品采买、CDK、采买、素材）。人力与常规工具不计
7. **风险与回滚**：每条写触发信号/应对/回滚。{{GAME_CN}} 特有风险是社区对商业化动作的敏感反弹——预案是立刻停止付费相关表述、转为内容向沟通，**不辩解**

**风险表 8 条打底**（准则 6.2）：版本日带宽挤占 / CDK 核销不及预期 / 实物缺货涨价 / 资源位被其他游戏挤占 / 回归目标落空 / 预估实测偏差 >30% / 素材触社区红线 / **版本延期**。
最后一条必须有独立预案（活动窗口顺延 or 预热周先行）——{{VERSION_NAME}} 这类大版本上线日是整个方案的时间锚点，延期则全盘失效，只写"与官方公告复核"等于没预案。

## 收尾检查清单

- [ ] 一句话目标含可度量结果
- [ ] {{DEVELOPER}} 审批排在 T-45；**若已超期，写明"只能用现有库存"+ 替代方案**
- [ ] 事实核对与资源位档期锁定都排在 T-30
- [ ] **T-30 已索取书面承诺曝光量与资源位清单**，并确认回归人群定向能力
- [ ] **风险表 ≥8 条且含版本延期预案**（窗口顺延 or 预热周先行）
- [ ] 渠道活动与版本日同步开跑（错峰的写明理由）
- [ ] 版本日带宽挤占有预案（双入口 + 动图降级）
- [ ] 内部排期口径的日期写了"对外发布前须与官方公告复核"
- [ ] 当前层级与放行阈值写清（常规节点活动可标 Durable）
- [ ] 有社区反弹应对预案
- [ ] 审核人已过红线自检七问
- [ ] {{PLATFORM_A}} 档位竞争与 T+1 延迟已考虑
