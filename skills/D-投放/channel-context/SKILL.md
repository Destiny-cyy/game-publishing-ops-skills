# 渠道运营上下文（单一事实源）

这个 skill 只产出一个文件：`_shared/context-template.md`。它是整套渠道工作的"大脑"——人群、产品线、渠道资产、红线、指标口径只写一次，后续所有 skill 先读它再开工。

借鉴来源：coreyhaines31/marketingskills 的 `product-marketing`、Theo7777/gtm-skills 的 `gtm-context`（共享 context + 版本 + changelog）。

## 开工前

按顺序找已有文件：

1. `_shared/context-template.md`（正主）
2. 工作区内的 `{{SOURCE_TABLE_FILE}}`、`{{SOURCE_TABLE_FILE}}`、`{{SOURCE_PLAN_FILE}}`

- **文件已存在**：读它，用不超过 5 行总结覆盖范围，列出缺口，问要补哪几节。**绝不覆盖重写**，只在原文件上追加/修订并写 changelog。
  - ⚠️ **改之前先 grep 现状**：需求方可能在预览里手改过，工具也可能注入脏属性或拿缓存版本覆盖。
- **准则层另有一份唯一真源**：`_shared/REDLINES.md`（口径 / 目标 / 活动 / 奖品 / 排期 / 踩坑 / 自检）。本文件只存**项目事实**（人群、台账、产品线），**准则不往这里复制**。
- **只有表格/文档**：读它们抽取事实，自动起草 V1。
- **都没有**：走下面的「新建流程」。

## 新建流程

推荐 **自动起草**：从工作区已有的三份材料里抽事实 → 出 V1 草稿 → 问用户"哪里错了、缺什么" → 迭代。
只有在材料完全缺失时才逐节问答，且一次只问一节。

优先级：**宁可标注"待确认"，也不要编造数据。** 事实性错误会被 {{GAME_CN}} 资料站与社区论坛 逐条纠错。

## 必须包含的 7 节

### 1. 产品与版本口径
- 服务器：**{{SERVER_LINE_A}}**（本方案唯一对象）；{{SERVER_LINE_B}}数据不互通、无交易系统、定价差异大 —— 与{{SERVER_LINE_B}}相关的任何表述必须显式区分，禁止混用
- 平台：PC（{{PLATFORM_A}} / 独立客户端）、主机、移动端覆盖情况
- 发行角色：{{DEVELOPER}}（{{DEVELOPER}}）官方 / 代理方 / 我们 —— 说清"我们是谁"，决定口吻边界
- 版本节拍：大版本、典藏版 发布、年度发布会 等固定节点

### 2. 目标人群（⚠️ 关键待确认项）
必须明确二选一或双轨，这直接决定后面所有渠道选择：
- **人群 A｜目标地区玩家用{{CHANNEL_TYPE_A}}玩{{SERVER_LINE_A}}**：渠道重心 {{COMMUNITY_VIDEO}} / {{MEDIA_CHANNEL}} / {{MEDIA_CHANNEL}} / {{COMMUNITY_FORUM}} / 论坛社区 / {{MEDIA_CHANNEL}}；痛点=网络、语言、支付、找不到组织
- **人群 B｜海外原生受众**：渠道重心 视频站 / 直播平台 / 社区论坛 / 社交平台 / 短视频平台 / 社群；痛点=内容同质化、回归门槛
- 每条人群写：画像一句话、核心痛点 3 条、他们聚集在哪、能接受什么语气

### 3. 产品线
以 {{VERSION_NAME_HIST}}文化主题线为主轴：角色/典藏版、外观、武器、活动、联动。
每条产品线写明：是什么、什么时候、可讲的卖点、**不可讲的雷区**。

### 4. 渠道资产台账
表格：渠道 / 账号 / 量级 / 负责人 / 历史素材表现 / 当前状态（自建 / 合作 / 未开）。
这是 channel-selection 打分的输入。

### 5. 商业与社区红线
直接引用 `../REDLINES.md`，不要在这里复制粘贴（避免两处失同步）。该文件含五类：社区性质 / 文化主题线 / 创作者合作 / 投放素材 / **数据与复盘 + 交付与文件**。

### 6. 成功口径
每个指标给出**定义 + 计算方式 + 数据来源 + 归因口径**。

**可比口径从场景档 `metrics.comparable` 取，件数不是规定**（{{AS_OF_DATE}} 修订）。默认档（{{CHANNEL_TYPE_A}}·预约期）：预约跳转 / 活动参与人数 / 加速人数环比 / 新进·回归加速 / 入库任务完成率 / 单客奖品成本 / CDK 核销率；{{CHANNEL_E}}档含「一键入库人数」与 CPS 销量；{{PLATFORM_A}} 档是预约人数 / CTR / 下载激活。
共同定义：参与人数按渠道自有口径、**不要求去重**、分渠道单列；加速环比 = 活动期 ÷ **活动前两周日均** − 1（分母避开前置活动收官周）；入库完成率 = 完成入库任务人数 ÷ 参与人数（**现行口径改为 页面点击率**：分母{{CHANNEL_COUNT}}家定义不一且按钮位置可操纵 CTR）。
**曝光率是履约验收项，不在效果可比层**；回归人数、CDK 核销率作补充项。「入库人数」只在渠道确实回传不了时才是禁用指标（{{CHANNEL_E}}能回传 → 不禁用）。

**不可比口径**：曝光量、点击、PV、抽奖人次——分渠道单列，**严禁相加**，不得作结案依据。

⚠️ **口径的权威定义在 `_shared/REDLINES.md` 第二章，本节只留指针、不复制内容**（复制就会两处失同步）。
口径不写清楚，复盘就是吵架。

### 7. 决策日志
日期 / 决策 / 依据 / 谁定的 / 是否可逆。只记结论不记过程。
