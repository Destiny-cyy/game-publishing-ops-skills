## ⚠️ 叙事原则（最重要，必须最先读）

> 这是业务方明确要求，**所有对外交付物（HTML 报告、{{DOC_TOOL}}、PPT）必须遵守**。

### 1. 客观展示"有优势的、进步的"一面
- 报告里**只写有优势的、环比进步的**内容。
- 太扎心的对比**不写进报告**：如"全周期垫底""19 分位""三款末位"这类表述**禁止出现在报告**。
- 扎心结论只在**内部沟通时口头/私信告知业务方本人**（见第 5 条）。

### 2. 大盘对比只保留"中位数"作参照
- 报告里**只列大盘中位数**，不列头部游戏名。
- 头部游戏名（{{BENCHMARK_GAME_A}}/{{BENCHMARK_GAME_B}}/无畏契约/CF/洛克/LOL 等）**禁止出现在报告**。
- 中位数是"及格线"，自身与中位数的差距是"进步空间"，叙事上更温和。

### 3. 对标游戏对比必须加曝光维度
- 对标游戏 = **{{BENCHMARK_GAME_A}}、{{BENCHMARK_GAME_A}}**（同为科幻/射击题材，量级接近）。
- 任何与对标游戏的对比，**必须同时给出曝光量**。只给 CTR 不给曝光 = 隐藏分母，是误导。
- **不占优的维度同样要列出并标注「待验证」**；只报优势会误导决策，也不符合数据纪律。

### 4. 优先用"对照实验/环比进步"叙事
- 好的叙事：用「前后两段时期 + 相对变化」讲清策略效果（数值填 `{{BASELINE_VALUE}}`，带区间与证据等级）
- 坏的叙事：把自身绝对值、大盘绝对值、排名一起摊开，且未标证据等级
- 前者是干净的因果故事（改了什么 → 好了多少），后者是排名羞辱。
- **所有结论优先用"改了什么 → 好了多少"结构**。

### 5. 扎心数据不进报告，但要告知业务方本人
- 排名、分位、垫底、与头部差距等扎心数据，**不进任何对外交付物**。
- 但必须在**交付时口头/私信告知业务方本人**，不能隐瞒。
- 目的：报告是给更上层看的，需要正向叙事；业务方本人需要真实情况做决策。

### 叙事自检清单（交付前逐条过）
- [ ] 报告里有没有"垫底/末位/倒数/分位/排名"这类词？→ 有就删。
- [ ] 报告里有没有头部游戏名（{{BENCHMARK_GAME_A}}/{{BENCHMARK_GAME_B}}/无畏契约/CF/洛克/LOL）？→ 有就删。
- [ ] 每个与对标游戏的对比是否都带了曝光维度？→ 没带就补，或删掉整条对比。
- [ ] 每个结论是否优先用了"改了什么 → 好了多少"结构？→ 没有就改写。
- [ ] 扎心数据是否已通过口头/私信告知业务方本人？→ 没有就在交付时补上。

## 一、口径声明（每次复盘报告开头必须写）

> **禁止混用**：唯一图口径 vs 投放记录口径，二者不能交叉计算。

### 模板

```
本次复盘数据口径：
- 时间范围：YYYY-MM-DD ~ YYYY-MM-DD
- 投放记录：M 条（每条 = 一次投放，含曝光UV、点击UV）
- 唯一图：N 张（按图片链接去重，N ≤ M）
- 复用比：M / N = X.X（平均每张图投放 X.X 次）
- CTR 口径：曝光加权 = SUM(点击UV) / SUM(曝光UV)，全部用投放记录口径
- 复用衰减口径：按唯一图聚合，看复用次数与 CTR 关系
- 节点映射：见 tag-taxonomy.md 第五节
- 大盘对标：{{BENCHMARK_GAME_A}}、{{BENCHMARK_GAME_A}}（游戏级 + 素材级双口径）
```

### 两条铁律
1. **CTR 一律用投放记录口径**（SUM点击 / SUM曝光）。唯一图口径只用于复用衰减分析。
2. **任何结论必须带三个数**：样本量 / 曝光量 / CTR。缺一不可。

## 二、CTR 计算口径

### 曝光加权（唯一正确口径）
```
CTR(组) = SUM(点击UV of 组内所有记录) / SUM(曝光UV of 组内所有记录) × 100%
```

### 禁止：简单平均
```
❌ CTR(组) = mean(每条记录的 CTR)   ← 大曝光记录被稀释，小曝光记录被放大
```

**原因**：一条曝光 500w 的素材和一条曝光 5w 的素材，对整体的贡献完全不同。简单平均会让小曝光素材的噪声主导结论。

**代码实现**：`analyze.py:agg` 函数，`CTR = clk / imp * 100`。

### 样本量门槛
- **样本 < 20**：标注「样本不足」，只给方向性结论（"似乎""倾向"），不给具体 CTR 数字对比。
- **样本 ≥ 20 且曝光 ≥ 50w**：可给正式结论。
- **样本 ≥ 20 但曝光 < 50w**：给结论但标注"曝光量小，需谨慎"。

## 三、六 + 一 分析维度

### 维度 1：整体月度
- **分组**：按 `投放日期[:7]`（YYYY-MM）。
- **输出**：每月的 样本 / 曝光 / 点击 / CTR。
- **用途**：看整体趋势，找环比进步故事。

### 维度 2：节点
- **分组**：按 `node_of(投放日期)`（6 档，见 tag-taxonomy 第五节）。
- **输出**：每个节点的 样本 / 曝光 / CTR。
- **用途**：看节点投放效率，判断哪些档期值得加投。

### 维度 3：画风
- **分组**：按 `画风` 字段（5 类，单选）。
- **输出**：每种画风的 样本 / 曝光 / CTR。
- **用途**：指导设计风格选择。

### 维度 4：画面元素（多选 LIKE 口径）
- **分组**：对 9 个元素取值，**逐个**筛选 `元素 in 画面元素` 的记录，分别计算。
- **关键**：多选字段不能用等值分组，必须用 LIKE/包含口径。一条记录可同时计入多个元素组。
- **输出**：每个元素的 样本 / 曝光 / CTR。
- **用途**：识别高效元素组合。
- **代码**：`analyze.py` 中 `res["元素"]` 段。

### 维度 5：福利呈现
- **分组**：按 `福利呈现` 字段（5 类，单选）。
- **输出**：每种福利呈现的 样本 / 曝光 / CTR。
- **用途**：验证"加福利"策略是否带来 CTR 提升（结论须由本期数据验证）。

### 维度 6：画风 × 福利交叉
- **分组**：`f"{画风}×{福利呈现}"`。
- **输出**：每个交叉组的 样本 / 曝光 / CTR。
- **样本门槛**：交叉组样本容易 < 20，务必标注样本量。
- **用途**：找最优画风+福利组合。

### 维度 7：复用衰减（唯一图口径）
- **聚合**：按 `图片链接` 去重，每张唯一图统计 复用次数 / 总曝光 / 总点击 / CTR。
- **分档**：1 次 / 2 次 / 3 次 / 4 次+。
- **输出**：每档的 图数 / 总曝光 / CTR 中位。
- **两个观察点**：
  1. **CTR 衰减**：复用次数 ↑，CTR 是否 ↓（素材疲劳）。
  2. **曝光结构倒挂**：高复用图的曝光占比是否异常高（说明在吃老本，没上新）。
- **代码**：`analyze.py` 中 `res["复用衰减"]` 段。

## 四、大盘 Benchmark（双口径）

### 游戏级口径（曝光加权）
- **数据源**：`bench.json`（游戏 × 月的 imp/clk）。
- **计算**：每游戏每月 `CTR = clk / imp`。
- **门槛**：曝光 ≥ 500w 的游戏才纳入排名。
- **输出**：
  - 大盘中位 CTR（每月 + 全周期）
  - {{GAME_CN}} / {{BENCHMARK_GAME_A}} / {{BENCHMARK_GAME_A}} 的 CTR + 排名 + 分位
- **用途**：判断 本游戏在量级相近游戏中的位置。

### 素材级口径（单张中位）
- **数据源**：`bench_materials.json`（单条素材 imp/clk）。
- **门槛**：单条曝光 ≥ 10w。
- **计算**：每游戏所有素材 CTR 的中位数，以及 本游戏中位在大盘中的分位。
- **输出**：
  - 大盘素材中位 CTR
  - 本游戏素材中位 CTR + 分位 + ≥1% 占比
- **用途**：判断 {{GAME_CN}} 单张素材的质量水位（不受曝光量影响）。

### 双口径差异
| 口径 | 分母 | 反映什么 | 用途 |
|------|------|----------|------|
| 游戏级 | 曝光加权 | 整体投放效率 | 看大盘位置 |
| 素材级 | 单张中位 | 单张素材质量 | 看设计水位 |

**两个口径可能矛盾**：游戏级高但素材级低 = 靠曝光堆量；游戏级低但素材级高 = 素材好但量不够。

### 对标游戏
- **对标游戏**：**{{BENCHMARK_GAME_A}}、{{BENCHMARK_GAME_B}}**（同题材、量级接近，按你的项目填）。
- **对比规则**：必须同时给 CTR + 曝光量；不占优的维度同样列出，并标注「待验证」。

## 五、结论写法模板

### 单维度结论
```
【画风·华丽鎏金风】CTR X.XX%（样本 N 张 / 曝光 XXw）
  vs 大盘中位 X.XX%（+/-X.XXpp）
  vs {{BENCHMARK_GAME_A}}同维度 X.XX%（曝光 XXw，本游戏曝光 XXw）
  结论：该画风在 {{GAME_CN}} 素材中表现[最优/中等/待优化]，建议[加大/维持/减少]该风格投放。
```

### 环比进步结论（优先使用）
```
【福利呈现·环比进步】
  早期阶段：多数素材无福利，CTR `{{BASELINE_VALUE}}`
  后期阶段：多数素材加福利，CTR `{{BASELINE_VALUE}}`
  结论：10 月起全面加福利后 CTR 环比 +16%，验证"加福利"策略有效，建议持续。
```

### 交叉维度结论
```
【画风×福利·最优组合】
  华丽鎏金风 × 独立圈圈式：CTR X.XX%（样本 N，曝光 XXw）
  是整体均值的 X.X 倍。
  结论：该组合为当前最优，建议 11 月主推。
```

### 复用衰减结论
```
【复用衰减】
  1 次投放：CTR 中位 X.XX%（N 张图）
  2 次投放：CTR 中位 X.XX%（N 张图）
  3 次+：CTR 中位 X.XX%（N 张图）
  结论：复用 [有/无] 明显衰减，建议单图复用不超过 X 次。
```

### 结论四要素（缺一不可）
1. **标签**：哪个维度、哪个取值。
2. **CTR**：曝光加权后的具体数字。
3. **对比基准**：大盘中位 / 对标游戏 / 环比基线。
4. **幅度**：差值（pp）或倍数。

## 六、缺口测算口径

用于回答"要达到某个 CTR 目标，需要补多少张某类素材"。

### 公式
```
目标 CTR = (现有点击 + 新增点击) / (现有曝光 + 新增曝光)
新增曝光 = (现有点击 + 新增点击) / 目标 CTR - 现有曝光
假设新增素材 CTR = 该类别历史最优 CTR
新增素材数 = 新增曝光 / 单张素材平均曝光
```

### 示例
```
目标：整体 CTR 从 `{{BASELINE_VALUE}}` 提升到 `{{BASELINE_VALUE}}`
现状：曝光 `{{BASELINE_VALUE}}`，点击 `{{BASELINE_VALUE}}`
假设新增素材 CTR = `{{BASELINE_VALUE}}`（某类画风历史均值，须带证据等级）
解：新增曝光 = (现有曝光 + x×`{{BASELINE_VALUE}}`) / 目标 CTR － 现有总曝光（数值全部由使用方填）
   单张素材均曝 = 50w
   需新增约 X 张华丽鎏金风素材
```

### 使用场景
- 向项目组申请素材制作资源时，用缺口测算说明"为什么需要 X 张新素材"。
- 缺口测算只给方向性结论，不承诺精确数字。
