## 二、画风（单选，5 类）

判定优先级：**实机画面 > 场景概念原画 > 华丽鎏金风 > 暗黑魔幻CG > 科幻写实CG**。
（先判断是否实机/原画这两类"形式型"，再在 CG 类里判断"风格型"）

### 1. 科幻写实CG
- **画面特征**：高精度 3D 渲染的科幻角色/角色，金属质感明显，光影写实。
- **色调**：明亮或中性调（冷蓝、银灰、暖白均可），整体明度中高。
- **典型元素**：科幻角色立绘、载具与科技建筑。
- **反例**：如果整体压暗、红黑阴森 → 走「暗黑魔幻CG」；如果金光泛滥 → 走「华丽鎏金风」。

### 2. 暗黑魔幻CG
- **画面特征**：暗色调、感染/邪异风，常见 异变生物、血肉或腐蚀纹理。
- **色调**：红黑、暗绿、阴森紫，明度低，饱和度偏高。
- **典型元素**：生物科技元素、大型异变首领与腐蚀武器特写。
- **边界**：如果只是背景暗但主体是干净角色金属质感 → 归「科幻写实CG」。

### 3. 华丽鎏金风
- **画面特征**：金色繁复装饰、浮雕、花纹，典藏/限定系列质感。
- **色调**：金为主，配白/黑/深蓝，明度中高，金属光泽强。
- **典型元素**：典藏角色、典藏武器与金色建筑。
- **边界**：如果金色只是点缀而主体是普通角色 → 归「科幻写实CG」。

### 4. 实机画面
- **画面特征**：游戏内实机截图，**有 UI 元素**（血条、技能栏、小地图、任务列表、伤害数字）或**战斗/移动视角**。
- **判定关键**：能看到 HUD 或典型第三人称越肩视角 → 即为实机。
- **边界**：如果只是截了游戏里的场景但没有 UI、没有角色 → 归「场景概念原画」。

### 5. 场景概念原画
- **画面特征**：环境场景为主（载具内部、地表、空间站或工业基地等），**角色很小或无角色**。
- **用途**：常用于版本前瞻、世界观宣传。
- **边界**：如果角色占画面 ≥ 1/3 → 归对应的角色画风类。

## 三、画面元素（多选，≤3）

按视觉占比从大到小选，**最多 3 个**。

| 取值 | 判定标准 |
|------|----------|
| 单角色立绘 | 画面主体是 1 个角色，站/坐/浮空 pose，无战斗动作 |
| 多角色拼条 | 2 个及以上角色并列展示（常见于版本主视觉、限定角色合集） |
| 角色战斗 | 角色有明显战斗动作（开火、挥刀、技能释放、命中特效） |
| BOSS怪物 | 画面主体是 BOSS/大型敌人（如大型首领、异变首领或精英敌人） |
| 场景风景 | 环境占主体，用于交代世界观/版本场景 |
| 装备道具 | 武器、角色部件、守护、载具等道具特写 |
| 大字文案 | 画面有明显的大号标题字（版本名、slogan、"新版本"等） |
| 实机 | 有游戏 UI/HUD 或战斗视角（与画风"实机画面"高度重合，但元素维度是独立标记） |
| 实物奖品 | 项目可选：显卡、游戏主机、耳机、平台虚拟币、手柄等实物图；仅在实际投放使用实物激励时启用 |

**多选规则**

- 优先选视觉占比最大的 3 个。
- 如果画面只有 1 个明显元素，就只标 1 个，不要硬凑。
- 「大字文案」+「实机」+「角色战斗」是常见的三选组合。
- 「实物奖品」几乎总是和「大字福利文案」一起出现。

## 四、福利呈现（单选，5 类）

判定优先级：**堆叠式 > 独立圈圈式 > 单品聚焦 > 大字福利文案 > 无福利**。
（先看有没有奖励物的视觉呈现，再看呈现形式）

### 1. 堆叠式
- **画面特征**：多个奖励物堆叠/散落/瀑布式排列，视觉上"一大堆"。
- **典型**：一堆积分解锁道具、一堆游戏内货币币、一堆武器堆成小山。

### 2. 独立圈圈式（本游戏最常见）
- **画面特征**：奖励卡片**横向排列**，每张卡片一个奖励，卡片有边框/底色。
- **典型**：登录奖励 7 日卡、版本福利 4 选 1 卡片。

### 3. 单品聚焦
- **画面特征**：只展示 1 个奖励物，居中/占主体。
- **典型**：单张显卡、单台 游戏主机、单把 典藏版 武器。

### 4. 大字福利文案
- **画面特征**：福利信息**以文字为主**（"登录送""免费领""0 元购"），无具体奖励物图片或奖励物很小。
- **典型**："新版本登录即送 100 游戏内货币" 大字海报。

### 5. 无福利
- **画面特征**：画面完全无福利/奖励信息，纯内容向（版本前瞻、世界观、角色展示）。

## 六、打标置信度（单选）

| 等级 | 判定 |
|------|------|
| 高 | 画面特征清晰，无歧义，直接可判 |
| 中 | 有 1 处边界模糊（如画风在科幻写实/华丽鎏金之间摇摆），但已选定 |
| 低 | 画面模糊/信息不足/多处边界模糊，标签仅供参考 |

**使用规则**：分析时默认纳入全部置信度；如某维度结论不稳，可回溯只看「高」置信度子集做敏感性检验。

## 七、边界处理说明

1. **画风冲突**：先判形式（实机/原画），再判风格（写实/暗黑/鎏金）。一张图不可能同时是"实机画面"和"华丽鎏金风"——如果有 UI 又金光灿烂，归「实机画面」。
2. **画面元素超 3 个**：按视觉占比截取前 3，其余舍弃。如确实难分主次，标置信度=中或低。
3. **福利呈现 vs 实物奖品元素**：「实物奖品」是**画面元素**（画面里有什么），「单品聚焦/堆叠式」是**福利呈现**（怎么呈现）。一张显卡海报 = 元素[实物奖品] + 福利[单品聚焦]。
4. **节点跨档**：以投放日期为准，不按素材上线日期。跨档素材（如 <投放日期>）按实际投放日期映射到对应节点。
5. **同一图多次投放**：图片链接相同 = 同一张图。打标只打一次（首次出现的 rowid），分析时按图片链接去重（见 playbook 第七维度）。

## 八、扩展原则（新增/修改类别前必答四问）

新增一个画风/元素/福利类别前，依次回答：

1. **是否互斥？** 新类别与现有类别在同一维度下是否互斥（单选维度必须互斥，多选维度允许共存）。
2. **只看画面可判？** 是否能仅凭画面可观测特征判定，不依赖文案/数据/主观判断。若需要读文案才能判 → 不合格。
3. **设计师可执行？** 设计师看到类别名是否能直接理解要做什么。若需要额外解释 → 命名/定义不合格。
4. **拆分后样本是否 ≥ 20？** 按历史数据估算，新类别下的样本量是否 ≥ 20。若 < 20，先合并到相近类别，等样本积累后再拆。

**四问全过才允许扩展。** 任何扩展必须同步更新本文档 + `analyze.py` 中的取值列表（如 `res["元素"]` 的硬编码列表）。
