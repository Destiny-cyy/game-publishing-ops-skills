# {{GAME_CN}} 素材复盘与打标

## 目的

把"素材长什么样"变成可量化、可对比、可指导生产的结构化字段，并据此产出复盘结论、行动建议与可复用的素材资产。

## 何时使用

- 需要对 {{GAME_CN}}在 {{PLATFORM_A}} 的投放素材做复盘、打标或效果归因
- 需要建立/扩展素材标签库、维护素材索引表、批量重命名素材图
- 需要测算某月素材缺口、输出排期与延展优先级
- 需要生成 HTML 复盘报告或{{DOC_TOOL}}

## 硬性规则（先读，违反会返工）

1. **原表一律只读**：数据源子表（如「{{BENCHMARK_GAME_C}}素材往期」「{{PLATFORM_A}}素材」）禁止修改。打标数据写入**新建子表**，绝不改原表。
2. **打标必须逐张看图**：画风/画面元素/福利呈现只能用多模态看图判读，**禁止仅凭广告标题/描述文字推断**；文字只作辅助线索。
3. **标签结构以用户手动维护的版本为准**：用户可能增删列。每次执行前先读取目标表现在字段，本地文件与文档说明同步对齐。
4. **图片缺失标"待人工"**，绝不用文字臆断填充。
5. **样本量 < 20 的组别只给方向性结论**，报告中标注"样本不足"。
6. **对外输出（简历/外部分享）用相对值**，不出现曝光绝对值与 CTR 点数值（见 `references/analysis-playbook.md`）。
7. **每张交付物必须声明口径**：「唯一创意图（去重后）」与「投放记录行数」是两个数，禁止混用。例：{{SAMPLE_RECORDS}} 条记录 = {{SAMPLE_UNIQUE_IMAGES}} 张唯一图。交付时主动说明用的是哪个。
8. **对外/可分享产物只用 CDN 网址**（`{{CDN_HOST}}`），**禁止出现本地路径**（如 `素材图/*.jpg` 或本机盘符开头的绝对路径）。本地文件夹只用于离线看图与打标。
9. **文档迭代不留旧版本内容**：口径升级后（如 v1→v2）必须**删除/替换**旧章节，禁止"新增一节 + 保留旧节 + 加一句'现行见第 X 节'"。修订说明类章节（"本次改了什么"）在定稿时一并删除。详见 `references/doc-sync.md`。

## 工作流

### 阶段 1：摸底与数据准备

1. 读取数据源子表结构（子表列表 → 字段列表），确认素材粒度与可用维度。
2. 运行 `scripts/fetch_materials.py`：拉取全量记录生成主表 CSV（rowid / 素材ID / 图片链接 / 曝光 / 点击 / 日期 / 分层 / 位置），并按图片链接去重下载唯一创意图。
   - 经验值：{{SAMPLE_RECORDS}} 条投放记录通常对应约 {{SAMPLE_UNIQUE_IMAGES}} 张唯一图——**按图打标、按记录回填**。
3. 抽样查看 8-10 张不同时期的图，校准标签体系（首次执行或体系变更时必做）。

### 阶段 2：建立或复用标签库

- 复用：直接读 `references/tag-taxonomy.md`（现行 v2：画风 8 类、画面元素 10 类、福利呈现 5 类 + 节点 / 分层 / 置信度）。
- 新建或扩展时遵循四条标准：**互斥穷尽**（单选互斥、元素可多选叠加）、**只看画面可判定**、**可执行**（每个标签对应明确做法）、**粒度适中**（避免拆太细导致样本不足）。

### 阶段 3：逐张看图打标

1. 按图数量拆成 5 批（每批约 28 张），**并行派发子智能体**逐张用 Read 打开图片判读，输出 JSON（style / elements / benefit / desc / conf）。提示词必须强调：真实观看图片、不得猜测、把握不足标"中"。
2. 主会话抽查 4-6 张校验质量。注意会话级图片缓存会让重复读图返回 unchanged——需复制文件并在 JPEG 头插入 COM 段绕过（见 `references/table-ops.md`）。
3. 运行 `scripts/label_merge.py` 合并各批标签，按"图→记录"映射生成打标 CSV（含节点标签）。

### 阶段 4：写入{{TABLE_TOOL}}

运行 `scripts/write_smarttable.py`：新建打标子表（字段类型 + 单选/多选选项）→ 分批写记录 → 设置列宽 → 回读校验。
字段选项必须与标签体系一致；{{COLLAB_PLATFORM}}接口限制见 `references/table-ops.md`。

### 阶段 5：效果分析

运行 `scripts/analyze.py` 或按 `references/analysis-playbook.md` 手工取数：
- 七维度：整体（月度趋势）、节点、用户分层、画风、画面元素（多选按 LIKE 口径）、福利呈现、**复用衰减**
- 复用衰减：运行 `scripts/reuse_map.py`，按图片链接去重成唯一图，看"第 N 次复用"的 CTR 衰减与曝光结构是否倒挂
- Benchmark：对照 {{PLATFORM_A}} 大盘表，按"游戏×月"聚合曝光加权 CTR，算 {{GAME_CN}} 排名与分位；**必须同时算游戏级与素材级两个口径**（见 playbook，两者结论可能相反）
- CTR 一律用**曝光加权**（SUM 点击 / SUM 曝光），不做简单平均

### 阶段 6：产出交付物

1. **HTML 复盘报告**：复制 `assets/report_template.html` 填入 KPI、核心结论卡、分维度表、Benchmark、缺口测算、⚡行动建议（深色卡片风格）。
2. **{{DOC_TOOL}}**：用 `{{TABLE_TOOL_CLI}} {{DOC_TOOL_PAGE}}` 创建/追加，承载打标体系定义、效果结论、索引说明、延展方向；长表按 25 行/块分批追加。
3. **文档对齐（口径升级时）**：按 `references/doc-sync.md` 执行"拉块 → 删旧 → 改标题 → 插新 → 校验"五步，改完必须 grep 关键词确认旧口径命中 0。
4. 用 `present_files` 展示交付物。

### 阶段 7：缺口测算与排期（资源规划类需求）

- 需求侧：投放天数 × 每日差异化张数（通常 2-3 张）
- 供给侧：现有套数中历史验证高 CTR、可延展复用的底稿数
- 净缺口 = 需求 − 可复用；**明确写出三条假设**（每日张数、复用率、版本换新缓冲）
- 输出 P0-P3 优先级 + "暂缓"清单 + 按周排期

## 关键脚本

| 脚本 | 用途 |
| --- | --- |
| `scripts/fetch_materials.py` | 拉原表数据 → 主表 CSV；去重下载唯一创意图 |
| `scripts/label_merge.py` | 合并各批打标 JSON → 打标 CSV（图→记录回填 + 节点标签） |
| `scripts/analyze.py` | 六维度曝光加权 CTR 聚合 + 大盘 Benchmark 排名 |
| `scripts/reuse_map.py` | 投放记录 → 唯一图，算复用次数与"第 N 次复用"CTR 衰减，输出 reuse_map.csv |
| `scripts/rename_images.py` | 按标签重命名为 `编号_画风-元素-福利_素材ID.jpg`，输出映射 CSV |
| `scripts/write_smarttable.py` | 建打标子表（选项/列宽）、分批写记录、回读校验 |

## 交付前自检清单

- [ ] 口径声明写了（唯一图 vs 投放记录、数据区间、数据来源）
- [ ] CTR 全部曝光加权，每个结论带 样本/曝光/CTR
- [ ] 样本 < 20 的组标注"样本不足"
- [ ] 大盘对比同时给了游戏级与素材级两个口径
- [ ] 含复用维度（老图反复投还有没有效）
- [ ] 产物中无本地路径，链接全是 CDN 网址
- [ ] 文档中无旧口径残留（grep 旧版本号/旧标签名/旧小节号 = 0 命中）
- [ ] 锚点资产（索引表、内置数据表）未被误改
